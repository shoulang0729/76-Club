## 1. 要件

### 1.1 ユーザー原文

> iPadで表示前提で画面サイズを最適化してほしいのですが ニアドラ２セットの際に、１画面でチーム勝敗と獲得者の名前が全部見えるようにしたい

### 1.2 PM 確認済みの前提（2026-09-12）

| 項目 | 回答 |
|---|---|
| 投影元 | **iPad を横向き**で使い、プロジェクターへ出力 |
| 最適化対象 | iPad 横向き（実効 CSS 幅 **1024〜1366px**・高さ **768〜1024px**） |
| 制約 | **横幅ではなく高さ**。縦に収まるかが勝負 |
| 「1画面」の定義（本書の解釈） | **チーム勝敗ヒーローカード ＋ 全ヒーローセル ＋ 開封チップ行**までがスクロールなしで見えること。最下部の**勝者登録パネル（`<details>`）は画面外でよい**（§11.14 原則3＝幹事操作は控えめ・スクロールで到達） |

### 1.3 ユーザーが挙げた改善アイデアの採否

| # | アイデア | 採否 | 節 |
|---|---|---|---|
| 1 | 2セット8枚を1画面に収める | **採用**（横一列＋高さ圧縮） | §4.3 |
| 2 | 区分ラベルを番号の横に置く | **採用（両方対処）**。OUT/IN は**勝者名と同じ行**へ／ニアピン・ドラコンは**番号と同じ行に収まるまで縮小** | §5.2 |
| 3 | チーム名を拡大 | **採用**（`.npdc-team` 13px → 最大22px） | §5.2-⑥ |

> **解釈の注記（§13-A で PM 確認）**: 「区分ラベル（OUT組/IN組）をホール番号の横に」は、**1つのホール番号に対して OUT/IN が2つある**ため文字どおりの配置（番号の右に2つ並べる）は成立しない。「**別行を食わない**」が意図と読み、OUT/IN は**それぞれの勝者名と同じ行**に置く（高さの節約効果は同じ＝1行あたり −23px）。あわせて、実際に折返して**52px も食っていた**ニアピン/ドラコン側も番号と同じ行に収める。

## 3. ★高さ予算（本設計の核心）

### 3.1 実効ビューポート高の仮定（★実測できないので仮定として明記する）

Safari のツールバー（タブバー＋アドレスバー）は iPadOS のバージョン・設定（「タブバーを表示」／「コンパクト」）で変わる。本書は**保守的に 108px** を仮定する。

| 端末（横向き） | CSS viewport | Safari 通常（**仮定 −108px**） | ホーム画面に追加（standalone・`apple-mobile-web-app-capable=yes` が index.html:5 にある） |
|---|---|---|---|
| iPad 9.7"/10.2"(768pt) | 1024 × 768 | **H_eff = 660** ← **最悪ケース＝設計目標** | 744〜768 |
| iPad 10.2"(810pt) | 1080 × 810 | H_eff = 702 | 786〜810 |
| iPad Air / Pro 11" | 1180 × 820 | H_eff = 712 | 796〜820 |
| iPad Pro 12.9" | 1366 × 1024 | H_eff = 916 | 1000〜1024 |

**実測手順（実装者が1回だけやる・PR 本文に貼る）**: 投影に使う iPad の Safari で `about:blank` ではなく本アプリを開き、アドレスバーに
`javascript:alert(innerWidth+'x'+innerHeight)` は使えない（iOS で無効）ので、**Safari の Web インスペクタ**または一時的に `console.log(innerWidth,innerHeight)` で確認する。仮定より小さければ §13-C の standalone 運用を推奨する。

## 4. レイアウト案の比較

### 4.1 前提：面積で見ると足りている

幅1024px・H_eff 660px で、グリッドに使える面積は **978 × 243 ≒ 237,000px²**。16名なら1名あたり **≒14,800px²**（例: 115×128）。**30px 級のフォントなら物理的に足りる**。足りていないのは「縦に積みすぎている」ことだけ。

### 4.2 案の比較（2セット・8ホール＝16名）

| | **案A（採用）横一列（列数＝ホール数・最大は幅で自動）** | 案B 4列×2行のまま高さだけ圧縮 | 案C 8列×1行（固定8列） | 案D セル内 OUT/IN を左右に並べる | 案E 表形式（ヘッダ行=ホール番号、行=OUT/IN） |
|---|---|---|---|---|---|
| 実装 | `grid-template-columns:repeat(auto-fit,minmax(112px,1fr))` | 既存のまま＋フォント縮小 | `repeat(8,1fr)` ＋ JS で列数計算 | セル内に2カラム | `.npdc-hero` を捨てて `<table>` へ |
| 1024 での必要高 | **581px** ✅ | 8列ぶんの高さ×2行 ⇒ 勝者名を **25.9px** まで落とさないと入らない ❌ | 581px（同等） | 名前の幅が **約100px** しか取れず 2〜3行に折返す ⇒ 高さが逆に増える ❌ | 500px 前後（最小） |
| ホール数が変わったとき | **auto-fit が自動追従**（4ホールなら4列で大きく、10ホールなら2行） | 常に4列 | JS で `--npdc-cols` を計算＝**JS 変更が増える** | 同左 | 同左 |
| 1セット運用との共存 | **`.two` の有無で minmax を切替**＝1行の差分 | ○ | 列数を S で分岐＝JS 必要 | × | × |
| np=青枠 / dc=赤枠（区分の機能色） | **セル単位で保持** ✅ | 保持 | 保持 | 保持 | **列単位になり弱まる** ⚠️ |
| 開封のタップ対象（`.npdc-row` 44px） | **そのまま** ✅ | そのまま | そのまま | 横幅が狭く誤タップ増 | `<td>` へ移設＝reveal-per-set §5.2 の再設計が要る ❌ |
| 既存 CSS の再利用 | **ほぼ全部**（`.npdc-*` をそのまま使う） | 全部 | 全部 | 一部 | **ほぼゼロ** ❌ |

**決定：案A**。決め手は ①`auto-fit` なので**ホール数に自動追従**して JS で列数を計算しなくてよい、②`.npdc-cell` の枠色・`.npdc-row` のタップ領域という **reveal-per-set の設計をそのまま維持**できる、③1セット/2セットの切替が `minmax()` の値1つで済む。

### 4.3 `minmax()` の下限値の決め方

| モード | 下限 | 幅1024 での結果 | 根拠 |
|---|---|---|---|
| **2セット**（`.npdc-hero.two`） | **112px** | (978+8)/(112+8) = 8.2 → **8列** | 8ホールを1行に収める最小値。これ以上大きくすると 1024px で7列になり2行化する |
| **1セット**（`.npdc-hero`） | **220px** | (978+8)/(220+8) = 4.3 → **4列** | **現行の @768 = 4列と一致**＝1セット運用の列数を変えない。コンテナ 222px で勝者名 `30cqw`=66px ⇒ `--f-rl-name`(44px) が**そのまま通る** |

`auto-fit` は空トラックを潰すので、**ホール数が列数より少なければセルが広がる**（6ホール → 6列に伸びて 156px、4ホール → 4列で 240px）。ホール数が多ければ自動で2行になる（§8-①）。

## 5. 表示仕様（CSS）

### 5.1 発動条件

```css
@media (min-width:1024px) and (min-aspect-ratio:4/3){ ... }
```

| 条件 | 理由 |
|---|---|
| `min-width:1024px` | iPad 横向きの下限（1024pt）。**820px 以下（スマホ・iPad 縦・狭幅PC）は完全に非接触** |
| `min-aspect-ratio:4/3` | 「横長」の判定。iPad 9.7" 横 = 1024/768 = 4/3（**等号を含むので成立**）／Safari ツールバー分だけ高さが減れば比はさらに大きくなる。**iPad 12.9" 縦（1024×1366 = 0.75）を確実に除外**できる |

- `max-height` は**付けない**（iPad Pro 12.9" 横 = 高さ1024px を弾いてしまうため）。副作用として**横長PC（例 1920×1080・1440×900）もこのモードに入る**が、投影用途として妥当なので許容する（§7.3 に明記）。
- `min-aspect-ratio` は Media Queries Level 3 の機能で Safari/Chrome/Firefox とも古くから対応。`:has()` は**使わない**（対応バージョンの下限を上げたくない・§6.1）。
