## 2. ユーザー回答の記録（2026-08-20・全確定）

1. **組合せ**: 「そもそも**2チームに分かれて1人ずつが対戦する**想定。例えば **8人のチーム対10人のチーム**のようなこともあり得る。この場合は8人チームの2名が2回出場することになるので、ルールとしては**全員が1回以上出場する**と決めたほうが良い」→ §4 のクロスマッチ抽選に反映。
2. **人数差（旧・奇数人数）**: 同上（少ない側の選手が複数回出場）。
3. **判定スコア**: エブリ適用後スコア（既定案どおり）。
4. **集計・配点・提供先**: 全部既定でOK（18H通しUP差「3UP」/「AS」・勝者+2pt/引分両者+1pt を賞金配分算入・β版のみ）。

- 細則（再戦回避・2回目出場者の相手選定・均等配分）は §4 のアルゴリズムで設計確定（総当たりの mod 方式により自動充足）。
- **3チーム以上は対象外**（案内文表示）。将来拡張の余地: チームペアごとのクロスマッチ総当たり等（本設計ではスコープ外・§12 メモ参照）。

## 3. 計算仕様（§3 追補・★load-bearing。実装は `js/calc.js` に純粋関数を追加するだけ）

### 3.1 判定スコア
- 各ホールの比較値 = `adjHole(g,pid,i)`（エブリ適用後・未入力/未開封は null）。**§3 既存の計算（ペリア/エブリ/HBH ほか）には一切触れない**。

### 3.2 ホール勝敗（新規関数）
```
m1HoleWin(g, pidA, pidB, i):
  a = adjHole(g,pidA,i); b = adjHole(g,pidB,i)
  どちらか null → null（そのホールは対象外＝スキップ）
  a < b → 'A' ／ b < a → 'B' ／ a === b → 'H'（ハーフ）
```

### 3.3 マッチ結果（新規関数）
```
m1Result(g, pidA, pidB):
  upA = 'A' のホール数, upB = 'B' のホール数, half = 'H' のホール数
  played = upA + upB + half
  diff = upA − upB      # 正=A勝ち・負=B勝ち・0=AS（引分）
  return { upA, upB, half, played, diff }
```
- 表記: `diff>0` → 「A {diff}UP」／`diff<0` → 「B {−diff}UP」／`diff===0 && played>0` → 「AS」／`played===0` → 「—」。
- タイブレーク（`tieBreak`）は**使わない**（マッチの引分は引分のまま）。

### 3.4 数値例（前後比較つき・受け入れ条件で使用）
Par = `[4,4,3,4,5,4,4,3,4, 4,4,3,4,5,4,4,3,4]`（newGame 既定）。
- A（エブリなし）生 = `5,4,4,5,6,4,5,3,4, 5,5,3,6,7,4,5,4,5`（計84）
- B（エブリ1＝各H−1）生 = `6,5,4,5,7,6,5,4,5, 6,6,4,6,8,5,6,4,6`（計98）→ adj = `5,4,3,4,6,5,4,3,4, 5,5,3,5,7,4,5,3,5`

| 基準 | Aの勝ちH | Bの勝ちH | ハーフ | 結果 |
|---|---|---|---|---|
| **確定＝エブリ後(adjHole)** | 1（H6） | 5（H3,4,7,13,17） | 12 | **B 4UP** |
| （参考）生スコア | 13 | 0 | 5 | A 13UP |

- 部分開封例: 上記で revealHoles=9 なら H1–9 のみ → A 1・B 3・ハーフ5 = 「B 2UP（暫定）」。

## 4. 組合せ（チーム間クロスマッチ抽選・確定版）

### 4.1 前提チェック
```
T = g.teams のうち「memberIds ∩ g.participants（選手マスターに実在）」が1人以上のチーム
|T| !== 2 → 抽選不可（案内文 m1.need2Teams）
```

### 4.2 抽選アルゴリズム（m1MakePairs）
```
X = shuffle(teamA の該当メンバー)   # teamA/teamB は g.teams の並び順（Fisher–Yates）
Y = shuffle(teamB の該当メンバー)
n = max(|X|, |Y|)                  # 試合数 = 大きい側の人数
pairs[i] = [ X[i mod |X|], Y[i mod |Y|] ]   （i = 0 .. n−1）
保存: g.match1v1 = { teamA: T[0].id, teamB: T[1].id, pairs }
```
- **保証される性質**（この mod 方式で自動充足＝細則の設計確定）:
  1. 大きい側チーム: **全員ちょうど1回**出場。
  2. 小さい側チーム: **全員1回以上**。各自の出場回数は `floor(n/|小|)` か `ceil(n/|小|)`（差は最大1・誰が多く出るかはシャッフル順＝ランダムで公平）。
  3. **同一カードの再戦なし**: 同じ組合せが重複するのは `i ≡ j (mod |X|)` かつ `i ≡ j (mod |Y|)` のときだけで、それは `lcm(|X|,|Y|) ≥ n` 試合目以降にしか起きない。
  4. 2回目出場者の相手は必ず**未対戦の選手**（大きい側は全員1回しか出ないため）。
- **同数（例 5vs5）**: n=|X|=|Y| の 1:1 対応＝全員ちょうど1回。
- **例（8人 vs 10人）**: teamA=10人(X)・teamB=8人(Y) → n=10。試合 i=0..7 は X0..X7 vs Y0..Y7、i=8,9 は X8 vs Y0・X9 vs Y1（シャッフル後の Y 先頭2名が2回目）。10試合・X全員1回・Y全員1回以上。

### 4.3 運用
- 実行タイミング: 1 on 1 タブの「組合せ抽選」ボタン（幹事操作）。**保存後は再読込でも不変**。「再抽選」は confirm（`m1.confirmRedraw`）の上で作り直し。
- **抽選後にチーム/参加者が変わった場合**: 保存済み `teamA/teamB` が現在の2チームと一致しない、または pair の pid が該当チームの参加メンバーでなくなった試合は表示・集計からスキップし、注記 `m1.stale`（再抽選を促す）を表示。

## 5. データモデル（§4 追補・後方互換）

- `game.formats.match1v1`: bool（既定 **false**。`newGame()` に追加）。
- `game.match1v1`: `{ teamA: null, teamB: null, pairs: [] }`
  - `teamA`/`teamB` = 抽選時の 2チームの `team.id`（`g.teams` の並び順）。
  - `pairs` = `[pidA, pidB]` の配列（pidA∈teamA・pidB∈teamB、§4.2 の抽選結果）。
- `game.points` に `m1win: 2`, `m1draw: 1`（`defaultPoints()` に追加）。
- **`migrate()` で既定補完**（既存 `golfCompe_v1` データはそのまま動く＝後方互換）。localStorage キー自体は不変。

## 6. ポイント配分（`computePoints` への追加・F.match1v1 ON 時のみ）

```
if(F.match1v1 && g.match1v1 && g.match1v1.pairs.length){
  各 [a,b]（§4.3 の有効性チェックを通った試合のみ）:
    r = m1Result(g,a,b)
    r.played === 0 → 配点なし
    r.diff > 0 → pts[a] += P.m1win
    r.diff < 0 → pts[b] += P.m1win
    r.diff === 0 → pts[a] += P.m1draw; pts[b] += P.m1draw
}
```
- **個人にのみ配点**（チームメンバー全員への加算はしない＝teamGross 等とは異なる）。複数回出場する選手は獲得機会もその回数ぶん（ユーザー許容済み）。
- α版（`chFormats` で match1v1=false）では集計されない（§11.12 C と同じ効き方）。

- §3 既存計算（ペリア/エブリ/ステーブル/オリンピック/キャロウェイ/握り/ベスト2/チームHBH/Vegas）は不変。1 on 1 は**新規純粋関数の追加のみ**。

## 10. 受け入れ条件
1. §3.4 の数値例で「B 4UP」（生スコア基準に切り替えた比較検算では A 13UP）。ハーフはどちらにも加算されない。
2. revealHoles=9 の部分開封で「B 2UP（暫定）」相当になる（未開封/未入力はスキップ）。
3. **抽選（同数・5vs5）**: 5試合・全員ちょうど1回。
4. **抽選（人数差・8vs10）**: 10試合・10人側は全員ちょうど1回・8人側は全員1回以上（2名だけ2回・3回以上なし）・同一カードの重複なし・2回目出場者の相手は未対戦者。
5. **2チーム以外（0/1/3チーム、または片方メンバー0）**: `m1.need2Teams` の案内のみ表示・集計/配点なし。
6. 再読込しても組合せ不変。再抽選で作り直せる。抽選後のチーム/参加者変更で無効試合がスキップされ `m1.stale` が出る。
7. ポイント: 勝者+m1win／引分両者+m1draw が**個人**の「ポイント配分」タブに反映（チーム全員加算はしない・F.match1v1 ON 時のみ）。既存ゲームのポイントに回帰差分なし。
8. α版では 1 on 1 タブ・設定トグル・配点とも非表示/非集計。β版で表示。
9. i18n 3言語キー集合一致・`node tools/verify.mjs` 通過。既存 §3 計算の数値回帰なし。
