## 3. 計算仕様（§3 追補・★load-bearing。実装は `js/calc.js` に純粋関数を追加するだけ）

### 3.1 判定スコア
- 各ホールの比較値 = `adjHole(g,pid,i)`（エブリ適用後・未入力/未開封は null）。**§3 既存の計算（ペリア/エブリ/HBH ほか）には一切触れない**。

### 3.2 ホール勝敗（新規関数）
```
m1HoleWin(g, pidA, pidB, i):
  a = adjHole(g,pidA,i); b = adjHole(g,pidB,i)
  どちらか null → null（そのホールは対象外＝スキップ）
  a < b → 'A' ／ b < a → 'B' ／ a === b → 'H'（ハーフ）
```

### 3.3 マッチ結果（新規関数）
```
m1Result(g, pidA, pidB):
  upA = 'A' のホール数, upB = 'B' のホール数, half = 'H' のホール数
  played = upA + upB + half
  diff = upA − upB      # 正=A勝ち・負=B勝ち・0=AS（引分）
  return { upA, upB, half, played, diff }
```
- 表記: `diff>0` → 「A {diff}UP」／`diff<0` → 「B {−diff}UP」／`diff===0 && played>0` → 「AS」／`played===0` → 「—」。
- タイブレーク（`tieBreak`）は**使わない**（マッチの引分は引分のまま）。

### 3.4 数値例（前後比較つき・受け入れ条件で使用）
Par = `[4,4,3,4,5,4,4,3,4, 4,4,3,4,5,4,4,3,4]`（newGame 既定）。
- A（エブリなし）生 = `5,4,4,5,6,4,5,3,4, 5,5,3,6,7,4,5,4,5`（計84）
- B（エブリ1＝各H−1）生 = `6,5,4,5,7,6,5,4,5, 6,6,4,6,8,5,6,4,6`（計98）→ adj = `5,4,3,4,6,5,4,3,4, 5,5,3,5,7,4,5,3,5`

| 基準 | Aの勝ちH | Bの勝ちH | ハーフ | 結果 |
|---|---|---|---|---|
| **確定＝エブリ後(adjHole)** | 1（H6） | 5（H3,4,7,13,17） | 12 | **B 4UP** |
| （参考）生スコア | 13 | 0 | 5 | A 13UP |

- 部分開封例: 上記で revealHoles=9 なら H1–9 のみ → A 1・B 3・ハーフ5 = 「B 2UP（暫定）」。

## 4. 組合せ（チーム間クロスマッチ抽選・確定版）【★§13.1 で廃止・上書き（抽選→手動）。§4.1 の前提チェックのみ存続】

### 4.1 前提チェック
```
T = g.teams のうち「memberIds ∩ g.participants（選手マスターに実在）」が1人以上のチーム
|T| !== 2 → 抽選不可（案内文 m1.need2Teams）
```

### 4.2 抽選アルゴリズム（m1MakePairs）
```
X = shuffle(teamA の該当メンバー)   # teamA/teamB は g.teams の並び順（Fisher–Yates）
Y = shuffle(teamB の該当メンバー)
n = max(|X|, |Y|)                  # 試合数 = 大きい側の人数
pairs[i] = [ X[i mod |X|], Y[i mod |Y|] ]   （i = 0 .. n−1）
保存: g.match1v1 = { teamA: T[0].id, teamB: T[1].id, pairs }
```
- **保証される性質**（この mod 方式で自動充足＝細則の設計確定）:
  1. 大きい側チーム: **全員ちょうど1回**出場。
  2. 小さい側チーム: **全員1回以上**。各自の出場回数は `floor(n/|小|)` か `ceil(n/|小|)`（差は最大1・誰が多く出るかはシャッフル順＝ランダムで公平）。
  3. **同一カードの再戦なし**: 同じ組合せが重複するのは `i ≡ j (mod |X|)` かつ `i ≡ j (mod |Y|)` のときだけで、それは `lcm(|X|,|Y|) ≥ n` 試合目以降にしか起きない。
  4. 2回目出場者の相手は必ず**未対戦の選手**（大きい側は全員1回しか出ないため）。
- **同数（例 5vs5）**: n=|X|=|Y| の 1:1 対応＝全員ちょうど1回。
- **例（8人 vs 10人）**: teamA=10人(X)・teamB=8人(Y) → n=10。試合 i=0..7 は X0..X7 vs Y0..Y7、i=8,9 は X8 vs Y0・X9 vs Y1（シャッフル後の Y 先頭2名が2回目）。10試合・X全員1回・Y全員1回以上。

### 4.3 運用
- 実行タイミング: 1 on 1 タブの「組合せ抽選」ボタン（幹事操作）。**保存後は再読込でも不変**。「再抽選」は confirm（`m1.confirmRedraw`）の上で作り直し。
- **抽選後にチーム/参加者が変わった場合**: 保存済み `teamA/teamB` が現在の2チームと一致しない、または pair の pid が該当チームの参加メンバーでなくなった試合は表示・集計からスキップし、注記 `m1.stale`（再抽選を促す）を表示。

## 5. データモデル（§4 追補・後方互換）

- `game.formats.match1v1`: bool（既定 **false**。`newGame()` に追加）。
- `game.match1v1`: `{ teamA: null, teamB: null, pairs: [] }`
  - `teamA`/`teamB` = 抽選時の 2チームの `team.id`（`g.teams` の並び順）。
  - `pairs` = `[pidA, pidB]` の配列（pidA∈teamA・pidB∈teamB、§4.2 の抽選結果）。
- `game.points` に `m1win: 2`, `m1draw: 1`（`defaultPoints()` に追加）。
- **`migrate()` で既定補完**（既存 `golfCompe_v1` データはそのまま動く＝後方互換）。localStorage キー自体は不変。

## 6. ポイント配分（`computePoints` への追加・F.match1v1 ON 時のみ）

```
if(F.match1v1 && g.match1v1 && g.match1v1.pairs.length){
  各 [a,b]（§4.3 の有効性チェックを通った試合のみ）:
    r = m1Result(g,a,b)
    r.played === 0 → 配点なし
    r.diff > 0 → pts[a] += P.m1win
    r.diff < 0 → pts[b] += P.m1win
    r.diff === 0 → pts[a] += P.m1draw; pts[b] += P.m1draw
}
```
- **個人にのみ配点**（チームメンバー全員への加算はしない＝teamGross 等とは異なる）。複数回出場する選手は獲得機会もその回数ぶん（ユーザー許容済み）。
- α版（`chFormats` で match1v1=false）では集計されない（§11.12 C と同じ効き方）。

### 13.1 手動ペア作成（§4.2〜4.3 の置き換え）

**前提チェックは §4.1 のまま**（有効チームがちょうど2。満たさなければ `m1.need2Teams` 案内のみ）。

**編集UI（幹事用・控えめ配置＝投影原則3）**: 対戦カード群の**下**に `<details class="m1-editwrap">` を置く。summary=`m1.edit`「組合せ（幹事用）」。**pairs が0件のときだけ `open` 属性で初期展開**（それ以外は折りたたみ＝投影の邪魔をしない）。中身:

1. **追加行**: `[select A（チームAの参加メンバー）] vs [select B（チームBの参加メンバー）] [追加ボタン m1.addPair]`
   - select の option ラベル = 選手名。既に n≥1 回登録済みの選手は `名前 ×n` 表記（出場回数が一目で分かる）。
   - 既定選択 = 各チームの**未出場選手の先頭**（全員出場済みなら先頭メンバー）。全員1回以上を自然に促す。
   - **追加時チェック（唯一のブロック）**: 同一カード（同じ `[pidA,pidB]` の組合せ）が既に pairs にあれば `toast(t('m1.dupPair'))` で弾く。それ以外（同一選手の再登場等）は常に登録可。
   - 初回追加時に `g.match1v1.teamA/teamB` を現在の `m1Teams(g)` の `T[0].id/T[1].id` で確定（以後 §4.3 の stale 判定は従来どおり機能）。
2. **登録済みリスト**: 1行=1組 `#番号 A名 vs B名 [↑][↓][×]`。↑↓で並び替え（先頭/末尾では disabled）、×で削除（confirm 不要・1組だけなので誤操作の被害小）。**この並び順＝対戦カードの表示順＝「一組ずつオープン」のめくり順**（幹事はここで演出順を制御。慣例に倣い注目カードを最後に置く等）。
   - §4.3 の stale で無効になった組（pid がチーム外に出た等）はリスト内に**赤字＋`m1.invalidPair` タグ**で表示し、×で削除できる（表示・集計からのスキップは従来どおり）。
3. **全削除ボタン**（`m1.clearAll`・`btn gray sm`）: confirm `m1.confirmClear` の上で `pairs=[]`・`teamA/teamB=null` に戻す。
4. **未出場警告**: 「両チームの参加メンバーのうち pairs に1度も現れない選手」がいる間、編集UI内と上部カードに `m1.notPlayed`（`未出場: {name}`・{name}=カンマ結合）を muted＋`color:var(--red)` で表示。**登録・集計はブロックしない**（運用ガイド）。pairs が0件のときは出さない（`m1.noPairs` 案内を優先）。

**関数（js/results.js・グローバル関数＋inline onclick 方式踏襲）**: `m1AddPair()` / `m1DelPair(idx)` / `m1MovePair(idx,dir)` / `m1ClearAll()`。いずれも `save()` → `renderResult()`。**削除**: `m1Shuffle` / `m1MakePairs` / `m1Draw`。

**保存・後方互換**: `game.match1v1={teamA,teamB,pairs}` の構造・migrate 既定・保存＝再読込不変・§4.3 stale 処理（無効組スキップ＋注記）は**全て維持**。抽選で作られた既存データもそのまま手動リストとして表示・編集できる（移行処理不要）。

### 13.2 オープン方式2択（表示状態・保存しない）

タブ内（開封バーのカード内・4ボタンの右）に **seg 切替**: `m1.modeAll`「全組一括」／`m1.modeOne`「一組ずつ」。

- **全組一括（既定）**: 現行どおり全対戦カードの結果を表示。
- **一組ずつ**: 各対戦カードは**伏せ状態**で表示 — 見出し（A vs B・選手名とチーム色）は見える、**中央の大型結果とホール表を隠し**、中央に大ボタン `m1.open`「オープン」。操作:
  - カードの「オープン」= そのカードを個別にめくる（任意順）。
  - 開封バー横に `m1.openNext`「次の組」（**未オープンの先頭＝リスト順**をめくる。全部開いたら disabled）／`m1.openAllCards`「全組オープン」／`m1.coverAll`「すべて伏せる」。
  - **めくり順の既定 = 登録リスト順**（幹事が §13.1 の並び替えで演出順を決める。任意カードの個別オープンも可）。
- **チーム対抗サマリ（上部カードの勝敗数）**: 一組ずつモードでは**オープン済みカードのみ集計**（未オープンの結果を漏らさない）。一括モードでは全有効試合（現行どおり）。
- **状態の持ち方（データ/表示状態の分離原則）**: `js/results.js` 冒頭にモジュール内変数 `let m1RevealMode='all'; let m1Opened=new Set();`（キー=`pidA+':'+pidB`。並び替え・削除に不変）。**localStorage には一切保存しない**（`revealHoles` と同じ揮発表示状態。再読込で 一括モード・全伏せに戻る＝仕様）。`golfCompe_v1` にも表示状態キーにも入れない。
- **配点への非影響**: `computePoints` はモード・カード開閉に**依存しない**（従来どおり有効試合×viewGame 基準）。

**revealHoles との主従（確定）**: **revealHoles（ホール開封）が主・カードオープンは従**。カードオープンは「revealHoles で開いている範囲の結果を、カード単位で見せる/隠す目隠しレイヤー」に過ぎない。
- 一組ずつモードでオープンしたカードも、中身（大型UPとホール表）は revealHoles 連動のまま: 未開封ホールは空欄・結果は暫定（`revealHoles<18` かつ played>0 なら大型表示の脇に `n/18H` タグ）。
- 開封バー（reset/prev/next/all）は両モードで従来どおり機能・表示。ホールを進めるとオープン済みカードの表示が更新される（伏せカードは伏せたまま）。
- これにより競合しない: 「ホールを1つずつ進める演出（主）」と「カードを1枚ずつめくる演出（従）」は独立に操作でき、未開封情報が漏れる経路がない。典型運用は「revealHoles=18（既定・全開）にして一組ずつモードでめくる」。

### 14.1 開封モデル（一組ずつモード・確定）

**状態（揮発・§11.14 原則4）**: `js/results.js` 冒頭を変更。

**マスクの実装方針（viewGame との関係・確定）**:

- renderMatch1v1Tab 内:
  - **全組一括**: `gv=viewGame(g0)` を全カード・サマリに使用（改修前と同一の見え方）。
  - **一組ずつ**: カードごとに `c=m1Opened.get(k)`（未オープンは undefined）を取り、**そのカードの表示・m1Result/m1HoleWin/adjHole は `viewGameN(g0,c)` 基準**で計算する。revealHoles はこのモードの m1 タブ表示に**関与しない**。

### 14.3 hero 中央寄せ（styles.css・数値確定）

**原因**: 現行 `.m1-hero` は `grid-template-columns:1fr auto 1fr` のため、広いカードでは各名前が「半分幅の列の中央」＝カード幅の約 25%/75% 位置に置かれ、端に散って見える。

**変更（`.m1-hero` を置き換え・`.m1-nm` に1行追加）**:
```css
.m1-hero{display:flex;justify-content:center;align-items:center;flex-wrap:wrap;
  column-gap:clamp(12px,4vw,48px);row-gap:4px;text-align:center;margin:4px 0 8px}
.m1-nm{ /* 既存の font-size:var(--f-rl-name) 等は維持し、以下を追加 */ max-width:38%}
```
- 名前・UP・名前が**内容幅でカード中央に密集**する。gap は clamp で画面幅に追従（スマホ12px〜投影48px）。
- `max-width:38%`＋既存 `overflow-wrap:anywhere` で長い名前は折り返し（2名合計 ≤76% で中央ブロックを圧迫しない）。極端に長い場合は flex-wrap で段落ち（許容）。
- 伏せ状態（中央がオープンボタン）も同レイアウト。hero 中央の暫定タグは従来どおり中央セル内の下段（`<div class="mt6">`）。
- 投影原則 §11.14 準拠: サイズ・色・トークンは §13.3 から変更なし（配置のみ）。
