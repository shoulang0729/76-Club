### 1.2 決定

**B を採用**。理由:

2. 概要サブタブは現状「ガイド4ステップ」を置く**案内専用の画面**であり、マニュアルの置き場として意味的に一致する（`home.step1..4` の詳細版がマニュアル、という親子関係になる）。

## 2. i18n の持ち方【確定】

### 2.1 前提となる制約（実測）

- `I18N` の現状: **394キー × 3言語**、ja 本文の総文字数 **6,396字**、`js/i18n.js` は **68,222 byte**。
- `tools/verify.mjs` の検査: ①ja/zh/en のキー数一致・欠落なし ②空値なし ③en にひらがな残存なし ④**使用キーの未定義参照なし** ⑤**未使用キーゼロ**（`js/**` ＋ `index.html` を走査し `'key'` の**引用符付き完全一致**があれば「使用」とみなす。動的連結は `DYN_PREFIX` allowlist）。
- 本マニュアルの本文量は ja **約9,800字**（§3 の内訳）。zh ≒ ja×0.85、en ≒ ja×1.6（既存 `rule.*` の実測比: ja 161字 / zh 139字 / en 258字）。**3言語合計 約34,000字**。

→ そのまま `I18N` に入れると **ja 辞書が 6,396 → 16,200字（+150%）**、`js/i18n.js` が **68KB → 約103KB** になり、「UI 文言辞書」が本文書に埋もれる。

### 2.2 比較

| 案 | キー数の見積り | 長所 | 短所 |
|---|---|---|---|
| **(a)** 段落ごとに `I18N` キー | 本文 約120キー ＋見出し32キー＝**152キー×3＝456エントリ**（現行394キーの1.4倍） | 粒度細かく差分が読みやすい | キー爆発。辞書が本文で埋まる。段落の増減でキー番号が動く |

### 2.3 決定 = (c)

`js/manual.js` を新設し、**目次(TOC)＋本文辞書＋描画関数**を1モジュールに閉じる。`tools/verify.mjs` に `MANUAL` 用の検査を追加する（§5）。

> **なぜ DYN_PREFIX を増やさなくて済むか**: 見出しキーは `MAN_TOC` の中に `titleKey:'man.c1'` のように**文字列リテラルで列挙**される。`js/manual.js` は verify の走査対象（`js/**` 全ファイル）なので、`'man.c1'` は引用符付き完全一致でヒットし「使用済み」と判定される。**`DYN_PREFIX` にも `KNOWN_UNUSED` にも追加は不要**（＝未使用キー検出の網を一切緩めない）。これは受け入れ条件（§6）で機械確認する。

### 2.5 データ構造（`js/manual.js`・実装スケッチ）

```js
/* ============================ MANUAL（アプリ内マニュアル・docs/handoff/2026-09-11-inapp-manual.md） ============================ */
/* 表示専用。計算・データモデル・localStorage には一切介入しない。開閉状態は揮発（非保存・§11.14 原則4）。
   タイトルは I18N（man.* / fmt.*）、本文は下の MANUAL。要約は既存 rule.* を再利用（重複を作らない）。 */

// 章 → 節。title=I18N キー / rule=要約に使う既存 rule.* キー（任意） / id=MANUAL の本文キー
const MAN_TOC = [
  { id:'c1', title:'man.c1', secs:[
    { id:'about', title:'man.s.about' },
    { id:'terms', title:'man.s.terms' },
    { id:'data',  title:'man.s.data'  } ]},
  { id:'c4', title:'man.c4', secs:[
    { id:'gross', title:'fmt.gross', rule:'rule.gross' },
    { id:'net',   title:'fmt.net',   rule:'rule.net'   }, /* … */ ]},
  /* … c2/c3/c5/c6/c7 … */
];

// 本文（HTML 可・許可タグは <b> <br> <ul> <li> <div class="rule"> のみ）
const MANUAL = {
  ja:{ about:'…', terms:'…', /* 38節 */ },
  zh:{ about:'…', /* 38節 */ },
  en:{ about:'…', /* 38節 */ },
};
function manText(id){ return (MANUAL[LANG] && MANUAL[LANG][id]) || MANUAL.ja[id] || ''; }
function renderManual(){ /* §4 の DOM を組み立てて文字列で返す */ }
```

- `LANG` は `js/i18n.js` のグローバル。ESM 化しない（CLAUDE.md）ので通常 `<script src>` で読み込み、`renderManual()` はグローバル関数。
- **inline `onclick` は追加しない**（ネイティブ `<details>` で完結＝新規グローバルハンドラ ゼロ）。
- 本文の許可タグは **`<b>` / `<br>` / `<ul><li>` / `<div class="rule">`（数値例ブロック）** のみ。すべて自前の静的文字列であり、ユーザー入力は混ざらない（`esc()` 不要）。

### 2.6 増補時のルール（以後の運用）

- 節を増やす = `MAN_TOC` に1行 ＋ `MANUAL.ja/zh/en` に1エントリずつ ＋ タイトルキーを `I18N` に3言語。**この3点セットが揃わないと verify が落ちる**（§5）。
- §3 の計算仕様を変更する PR は、**該当節の `MANUAL` 本文も同一 PR で更新**する（本設計の受け入れ条件に含める運用ルール。正本 §3 側の記述と食い違ったら §3 が優先）。

**`peria` の数値例（本文に必ず入れる・実装者はこの値をそのまま使う）**

- 前提: Par 72・係数 0.8・上限なし・エブリなし。隠し12ホールの合計が **60**。
- 規定打数 = 72（18H の合計パー）。
- `HDCP =（60 × 1.5 − 72）× 0.8 =（90 − 72）× 0.8 = 14.4`
- グロス 96 の人 → `ネット = 96 − 14.4 = 81.6`
- **エブリツー（E2）の人**は、隠し12H の各ホールから先に2打引いた値で合計する（12H なら −24）。上の例で素の隠し12H 合計が 84 なら `84 − 24 = 60` を式に入れる → HDCP 14.4、グロス（エブリ適用後）120−36=84 … のように**エブリが先・ペリアが後**であることを明記。

## 9. 触らない範囲（load-bearing）
