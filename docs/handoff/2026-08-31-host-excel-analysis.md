## 0. プライバシー方針

幹事Excel には実在の参加者氏名が入っている。**本書では氏名を一切書かない**。
選手は「T大#5（ロースター5番目）」「K大#12」のように**所属＋名簿順の番号**で表す。

**学校名は伏せ字にする**（2026-09-06 ユーザー指示）。実在校名を頭文字＋「大」に置換し、以下の対応で統一する:

| 本書の表記 | 意味 |
|---|---|
| **T大** | 主催側の大学（幹事Excel の `集計!B1` 等に固定で入っている方） |
| **K大** | 対戦相手の大学（定義名 `AITE` が指す方。今回の開催回の相手） |
| **Q大** | 前回開催回の相手校（`④HK!AD7` 等にハードコードで残っている残骸） |

Excel 内部の識別子（シート名・定義名）も学校名を含むものは同様に伏せる。原本では実在校名のローマ字表記や漢字が入っているが、本書では `集計(K大)` / `⑤HJ!<T大の定義名>` のように置換して記載する。**セル座標・数式そのものは原本どおり**なので、原本と突き合わせれば検証できる。

外部リンク先のオンラインストレージ URL も個人パスを含むため記載しない（§9.5 で存在のみ指摘）。

## 2. `score` — スコア台帳（PMが解析済み・引用元として再掲）

### 2.1 レイアウト（実測）

| 範囲（幹事Excel `score`） | 内容 | 代表式 |
|---|---|---|
| `C3:U4` | ホール名（`W1..W9` / `N1..N9`）と par | `D4=5, E4=3, ... U4=4`（合計72） |
| `B列` | Every 支給（今回は全空＝未使用） | 手入力 |
| `D5:U…` | 生スコア（`D1='Every前'`） | 手入力 |
| `Y:AT` | エブリ適用後ブロック | `Z5 = D5-$B5` … `AT5 = SUM(AR5:AS5)` |
| `AU2:BL2` | 隠しホール判定 | `AU2 = IFERROR(VLOOKUP(AU3,③DP!$A:$A,1,FALSE),"")` |
| `AU5:BL5` | 隠しホール別 HDCP 寄与 | `AU5 = IF(AU$2="","",MIN(AU$4,(Z5-AU$4))*1.2)` |
| `BM5` | HDCP | `=MIN(SUM(AU5:BL5),36)` |
| `BN5` | ネット | `=$AT5-BM5` |
| `BP:BY` | 学校別グロス順ソート（③DP の名前列を供給） | §2.3 |

par 実測: `W1..W9 = 5,3,4,4,4,4,4,3,5`(36) / `N1..N9 = 4,5,3,4,4,3,5,4,4`(36) → 72。
隠し12ホールは `W1,W2,W4,W5,W6,W7,N1,N4,N5,N6,N7,N9`、その par 合計 = **48**。

### 2.2 ペリア式の等価性（数式で証明＋実データで検証）

幹事Excel: `HDCP = MIN( Σ_{隠し12} min(par_i, adj_i − par_i) × 1.2 , 36 )`
76-Club（§3・既定）: `HDCP = clamp0( (Σ_{隠し12} adj_i × 1.5 − 72) × 0.8 )`, 上限 `periaCap`

**ダブルパーカットが1ホールも発動しない場合**（全ホールで `adj_i ≤ 2×par_i`）:

```
幹事Excel = Σ(adj_i − par_i) × 1.2 = 1.2·Σadj_i − 1.2×48 = 1.2·Σadj − 57.6
76-Club   = (1.5·Σadj − 72) × 0.8              = 1.2·Σadj − 57.6
```

→ **隠し par 合計が 48 のときに限り恒等**。48 でなければ一致しない（幹事Excel は隠し par 合計に依存、76-Club はコース全体 par 合計72に依存）。

**カットが発動すると乖離する。** 実データ24名で全数照合した結果（`adj_i > 2·par_i` のホールを持つ選手のみ差が出る）:

| 選手 | エブリ後グロス | 隠し12合計 | 幹事Excel HDCP | 76-Club 既定 HDCP | 差 |
|---|---:|---:|---:|---:|---:|
| T大#3 | 92 | 61 | 15.6 | 15.6 | 0（PM の検証例と一致） |
| T大#8 | 108 | 71 | **25.2** | 27.6 | −2.4 |
| K大#1 | 93 | 64 | **18.0** | 19.2 | −1.2 |
| T大#11 | 119 | 78 | **34.8** | 36.0 | −1.2 |
| K大#10 | 104 | 74 | **28.8** | 31.2 | −2.4 |
| T大#2 | 95 | 66 | **16.8** | 21.6 | **−4.8** |
| T大#10 | 125 | 82 | 36.0 | 40.8→(cap36) 36.0 | 0（上限で吸収） |
| T大#9 | 115 | 77 | **32.4** | 34.8 | −2.4 |
| K大#12 | 110 | 76 | **30.0** | 33.6 | −3.6 |

（他15名は一致。幹事Excel 側の値は `BM列` のキャッシュ値と小数誤差の範囲で完全一致することを確認済み。）

**結論**: `g.periaDblPar=true` ＋ `g.periaCap=36`（＋負HDCPを扱うなら `g.periaAllowNeg=true`）で **幹事Excel の個人ネットを完全再現できる**。PR #118 で既に手当て済み。**追加実装は不要**。

補足: カット発動条件は `adj_i > 2×par_i`。ちょうどダブルパー（`adj_i = 2·par_i`）は**カットされない**（`MIN(par, 2par−par) = par`）。76-Club の `Math.min(v, 2*g.par[i])` も同じ境界。**一致**。

### 2.3 学校別グロス順ソート（`BP:BY`）— ③DP への供給

```
BP5 = IFERROR(VLOOKUP(Y5,list!G:H,2,FALSE),"")          ← 所属校
BQ5 = IFERROR(IF($BP5=BQ$4,$AT5+ROW(BQ5)/10000,""),"")  ← 相手校(BQ4=AITE)のグロス+ε
BR5 = IFERROR(IF($BP5=BR$4,$AT5+ROW(BR5)/10000,""),"")  ← T大(BR4)のグロス+ε
BS5 = IF(BQ5="","",RANK(BQ5,BQ:BQ,1))                   ← 相手校内グロス順位
BT5 = IF(BR5="","",RANK(BR5,BR:BR,1))                   ← T大内グロス順位
BU5 = Y5                                                 ← 氏名
BX5 = IFERROR(VLOOKUP(BW5,BT:BU,2,FALSE),"")            ← T大 n位の氏名
BY5 = IFERROR(VLOOKUP(BW5,BS:BU,3,FALSE),"")            ← 相手校 n位の氏名
```

ε(`ROW/10000`) は同グロスの RANK 重複回避。ここでは**表示順にしか効かない**ので害はない（③DP の J/V 列の ε とは別物・そちらは §9.1）。

## 3. `list` / `使い方` / `input help` — 名簿・運用・入力補助

### 3.1 `list`

| 列 | 内容 | 式 |
|---|---|---|
| `A` | 連番 | `A2 = A1+1` |
| `B` / `C` | T大 / 相手校のロースター（**ランキング順に手入力**） | 手入力 |
| `D` | 組名（`【西1組目】`〜`【北3組目】`＝6組） | 手入力 |
| `E` | 組内通番 | `E1 = IF(I1="","",COUNT(I$1:I1))` |
| `H` | その枠の学校（`T大` / `=AITE` 交互） | 手入力／`=AITE` |
| `I` | ロースター番号（手入力＝パーティ分け） | 手入力 |
| `G` | 枠の氏名 | `G1 = IFERROR(IF(H1="T大",VLOOKUP(I1,$A:$C,2,FALSE),VLOOKUP(I1,$A:$C,3,FALSE)),"N/A")` |

## 4. `①ND` — ドラコン・ニアピン対決

### 4.1 何を計算しているか

```
E3 = IF(D3="","",VLOOKUP(D3,list!G:H,2,FALSE))   ← 氏名→所属校
F3 = IF($E3=F$2,1,"")   F$2 = "T大"
G3 = IF($E3=G$2,1,"")   G$2 = =AITE
F20 = SUM(F3:F19)  /  G20 = SUM(G3:G19)
集計!B2 = ①ND!F20 , C2 = ①ND!G20 , D2 = IF(B2=C2,"ドロー",IF(B2>C2,T大,相手校))
```

= **獲得本数の単純多数決**。実データ: T大 7 / K大 9 → K大勝ち。

### 4.2 構造（重要）

行3-10 が1ブロック目（`B3='ドラコン(W)'`, `B7='ニアピン(W)'`）、行11-18 が2ブロック目（`B11='ドラコン(N)'`, `B15='ニアピン(N)'`）。**両ブロックとも同じ8ホールを対象にしている**:

| 賞 | 対象ホール | par |
|---|---|---|
| ドラコン | `W1, W9, N2, N7` = 1,9,11,16H | すべて par 5 |
| ニアピン | `W2, W8, N3, N6` = 2,8,12,15H | すべて par 3 |

(W)/(N) は**スタートコース別の組**（西スタート組／北スタート組）を表す。つまり **8ホール × 2組 = 16賞**。合計 7+9 = 16 で整合。

### 4.3 76-Club との1対1突合

| 項目 | 幹事Excel `①ND` | 76-Club | 判定 |
|---|---|---|---|
| 対象ホールの決め方 | `C列`に手入力（`使い方!E14`） | `niapinHolesOf(g)=par===3` / `draconHolesOf(g)=par===5`（`js/state.js:72-73`） | **一致**（このコースでは NP={2,8,12,15}, DC={1,9,11,16} で完全一致） |
| 勝者の記録 | 氏名を D列に選択（`MEMBER` ドロップダウン） | `g.prizes.niapinWinner[h]` / `draconWinner[h]`（ホール→pid） | 一致（表現形式が違うだけ） |
| チーム集計 | `SUM` で本数 | `niadoraTeamCount(g,T)`（`js/calc.js:192-198`） | **一致** |
| 勝敗判定 | 本数多い方・同数はドロー | `teamWinPoints` の `add('niadora', nd,'desc')`（同点は勝ち点山分け） | **一致**（ドローの扱いは §8 参照） |
| **1ホールに複数勝者** | **可**（組ごとに独立） | **不可**（`niapinWinner[h]` は pid 1つ） | **76-Club に機能がない** |
| チーム未所属者の扱い | `VLOOKUP` が `N/A`→どちらにも入らない | `T.memberIds.includes(pid)` 判定でどのチームにも数えない | **一致** |
| 個人配点 | なし | `computePoints` で `P.niapin`/`P.dracon` を加算 | **幹事Excel にない**（76-Club のみ） |
| 同一人物の複数受賞 | 可（実データでK大#11 が W1・W9 の2本） | 可（別ホールなら可） | 一致 |

**差分の評価**: 「1ホールに複数勝者（スタート組別）」が76-Club に無い。取り込むなら `g.prizes.niapinWinner[h]` を `pid | pid[]` に拡張し、`niadoraTeamCount` / `results.js:155` の表示を配列対応にする必要がある。**§4 データモデルに触る = load-bearing**。ただし76-Club 側で「組」を持たないため、実質は「1ホール複数勝者を許す」という緩い一般化になる。

## 5. `③DP` — 全国大学対抗ルール（ダブルペリア＋足切り）

PM 解析済み事項は前提とする。ここでは**数値の裏取り**と**76-Club関数との1対1対応**を追加する。

### 5.1 数式（T大側 J列 / 相手校側 V列）

```
H4 = SUM(F4:G4)                                  グロス（エブリ後・score!AR+AS）
I4 = VLOOKUP(E4,score!$Y:$BN,41,FALSE)           HDCP（score!BM = Wカット・上限36）
J4 = H4 - I4 + ROW(J4)/100001 + H4/10001         ★T大側のネット（ε 2項）
V4 = T4 - U4 + ROW(V4)/100000                    ★相手校側のネット（ε 1項）
K4 = RANK(J4,J$4:J$17,1)                         校内ネット順位
L4 = IF(K4 <= COUNT(I$4:I$17) - ROUNDDOWN((COUNT(I$4:I$17)-5)/2,0), J4, "足切")
L18 = AVERAGE(L4:L17)   ← "足切"は文字列なので AVERAGE が無視する（正しく採用者のみ平均）
集計!D4 = IF(B4=C4,"ドロー",IF(B4<C4,T大,相手校))   B4=③DP!L18, C4=③DP!X18
```

### 5.2 採用人数（幹事Excel vs 76-Club）

幹事Excel: `N = P − ROUNDDOWN((P−5)/2, 0)`
76-Club: `uvTargetN(P) = Math.min(P, Math.round(5 + (P−5)*0.5))`（`js/calc.js:143`）

P=1..20 で一致（PM 確認済み）。実データ: T大 P=11 → N=8、K大 P=12 → N=9。**幹事Excel のキャッシュ値（"足切"3件ずつ）と一致**。

### 5.3 平均ネットの数値検証（★76-Club と完全一致）

幹事Excel を ε 抜きで再計算した結果と、76-Club の `uvNetA`（Wカット＋0クリップ＋上限36）で計算した結果:

| | T大 | K大 | 勝者 |
|---|---:|---:|---|
| 幹事Excel `L18`/`X18`（ε込み・実際の表示値） | 78.38509149805 | 76.55564888889 | K大 |
| ε を除いた真の採用平均 | **78.375** | **76.555556** | K大 |
| 76-Club `uvStanding` の `r4[0]`（採用平均ネット） | **78.375** | **76.555556** | K大 |
| （参考）76-Club §3 の `netScore` で同じ足切りをした場合 | 77.175 | 75.755556 | K大 |

**76-Club の大学対抗（`uvNetA`/`uvStanding`）は 幹事Excel の ③DP を数値レベルで再現している**。採用メンバーの集合も一致（K大側の同値2件の順序だけ入替、集合は同一）。

### 5.4 1対1突合表

| 項目 | 幹事Excel `③DP` | 76-Club `uvStanding`(`js/calc.js:169-190`) | 判定 |
|---|---|---|---|
| グロス | `score!AR+AS`（エブリ適用後） | `uvGrossA`（`g.univ.every` ONでエブリ後・既定OFF＝生スコア） | **差分**（幹事Excel は常にエブリ後。今回エブリ空なので実害なし） |

### 5.5 「どちらが規定に忠実か」

- **HDCP 上限**: `使い方!C21` は「HD上限36」としか書いていない。**幹事Excel（男女とも36）が文面に忠実**。76-Club の「女40」は §11.20 で別途決めた拡張（大会規定の一般的な運用に寄せたもの）。→ 取り込むなら「上限を男女共通にするオプション」が要る。**`uvHdcpA` は §3 直系ではないが計算仕様＝load-bearing 扱い**。
- **負のHDCP**: 幹事Excel は `MIN(sum, 36)` だけで下限クランプが無いため、隠し12ホールが par 合計48を下回ると**負のHDCP**（ネットがグロスを上回る）になる。実データでは全員正だが、テスト行では −1.2 / −4.8 が発生することを確認した。規定にどちらとも書かれていない。個人戦側は PR #118 の `periaAllowNeg` で選択可になっている。**大学対抗側（`uvHdcpA`）には同オプションが無い**。
- **タイブレーク**: 幹事Excel は**無い**（ε がある分むしろ有害・§9.1）。76-Club の4段タイブレークの方が実運用上まとも。**76-Club の方が良い。取り込み不要**。

## 9. 幹事Excel 側のバグ・不整合（実データで再現確認済み）

### 9.1 【B】③DP のタイブレーク ε が左右非対称で、平均値そのものを汚染する

V4 = T4 - U4 + ROW(V4)/100000                ← 相手校側：1項（グロス項なし）
```

`L18 = AVERAGE(L4:L17)` は ε 込みの `J` をそのまま平均するため、**T大の平均だけ約 +0.010 かさ上げされる**。

実測: T大 `78.38509149805` − 真値 `78.375` = **+0.010091**、K大 `76.55564888889` − 真値 `76.555556` = **+0.0000933**。
**正味 +0.009998 がT大に不利**（③DP は低い方が勝ち）。今回の差は 1.83 打なので結果は変わらないが、**0.01 打差以内なら誤判定する**。

さらに、ε は**足切りの当落も左右する**。実データでK大に「ネット 80.0 が2人」おり、9位（採用）と10位（足切）に ε で機械的に分かれている。今回は同値なので平均に影響しなかったが、**同ネットで別の値の組み合わせなら平均が変わる**。

修正案（幹事Excel側）: `V4` も `H4/10001` 相当を持たせて対称にする、かつ `L18` を `AVERAGEIF` ではなく ε 抜きの列で取る（ε 専用の隠し列を分ける）。
**76-Club 側は影響なし**（`uvStanding` は ε を使わず 4 段タイブレークで解決）。

### 9.2 【A】`list!M11` のコピペミス — ②MP のペアが6組目以降ズレ、1名が二重出場

```
M9  = VLOOKUP($A5,$A:$C,2,FALSE)   T大#5
M10 = VLOOKUP($A5,$A:$C,3,FALSE)   K大#5
M11 = VLOOKUP($A5,$A:$C,2,FALSE)   ★T大#5（本来は $A6 = T大#6）
M12 = VLOOKUP($A6,$A:$C,3,FALSE)   K大#6
M13 = VLOOKUP($A6,$A:$C,2,FALSE)   T大#6
M14 = VLOOKUP($A7,$A:$C,3,FALSE)   K大#7
…（以降 T大#k ↔ K大#(k+1) のまま最後まで）
```

結果のペア（`②MP!C7:C30` のキャッシュ値で確認）:

| 組 | T大 | K大 | 想定（同ランク対戦） |
|---|---|---|---|
| 1〜5 | #1〜#5 | #1〜#5 | OK |
| 6 | **#5（重複出場）** | #6 | #6 vs #6 |
| 7 | #6 | #7 | #7 vs #7 |
| 8 | #7 | #8 | #8 vs #8 |
| 9 | #8 | #9 | #9 vs #9 |
| 10 | #9 | #10 | #10 vs #10 |
| 11 | #10 | #11 | #11 vs #11 |
| 12 | #11 | #12 | （T大は11名なので本来不成立） |

`使い方!E4` が「**ランキング順に並べて入力**」と指示している通り同ランク対戦が意図なので、**6組目以降の全ペアが1つズレている**。加えてT大#5 が2試合出て、その勝利が `H5` に**2回カウントされている**（実データでT大#5 は G=+3 の勝ち）。

### 9.3 【A】`②MP!H5`/`I5` の SUM 範囲が2行足りない

```
H5 = SUM(H6:H28)     I5 = SUM(I6:I28)
```

ペアは行 7〜30（12組×2行）。**行29・行30 が集計から漏れている**。

実測: `I5` のキャッシュ値 = **7**。行30（K大#12）の `I30 = 1` を含めた正しい合計は **8**。
→ **相手校の勝利数が1つ少なく表示されている**（`集計!C3` に直結）。今回は 4 vs 7 → 4 vs 8 でも勝者は変わらないが、**1差の局面なら勝敗が反転する**。

正しくは `SUM(H7:H30)` / `SUM(I7:I30)`。

### 9.4 【A】`DP_RT` — 行10 の par 参照が全て #N/A（シート全体が機能していない）

```
B10 = HLOOKUP(B9, score!$Z$3:$AQ$4, 2, FALSE)
```

`B9` は**ホール番号（数値 5, 8, 1, …）**、`score!$Z$3:$AQ$3` は**ホール名（文字列 'W1','W2',…）**。型が合わないので **B10:T10 の18セル全てが #N/A**（キャッシュ値で確認）。
比較: `④HK!D8` と `Roulette!B2` は同じ `HLOOKUP` を**ホール名**で引いており正常。

さらに固定の par 見出し行 `B5:T5`（`3,3,5,5,4,4,4,4,4` ×2）が行9のホール割当と合っておらず、**18選択肢中6つで par 表示が実際と違う**:

| 選択肢 | 行5の par | 行9のホール | 実際の par |
|---|---:|---:|---:|
| A | 3 | 5H | 4 |
| E | 4 | 2H | 3 |
| J | 3 | 14H | 4 |
| K | 3 | 16H | 5 |
| M | 5 | 15H | 3 |
| O | 4 | 12H | 3 |

加えて出力（`B14:B25`）は**ホール番号**を返すが、`③DP!A4:A15` が求めているのは**ホール名（'W2' 等の文字列リテラル）**なので、出力をそのまま貼っても繋がらない。
→ **`DP_RT` は現状デッドシート。隠しホールは `③DP!A4:A15` に人が直接ホール名を打ち込んで運用している**（実際 `A4:A15` は数式ではなくリテラル）。

`B13` の参照も怪しい: `=IF(AND(B12<>0, B12<>A13), B9, "")` の `A13` は見出し文字列 `'Copy'`。数値 vs 文字列の比較なので常に TRUE となり**偶然動く**（意図は「左隣の COUNTA と比べる」だが1列目に左隣が無い）。

### 9.5 【C】前回大会ブックへの外部リンクと壊れた定義名が残っている

`xl/externalLinks/externalLink1.xml` が 2021年開催回の別ブック（オンラインストレージ上）を参照している。これに紐づく定義名が壊れている:

```
VETERAN     = INDIRECT("list!O1:O" & COUNTA([1]list!#REF!))     ← #REF!
WAKATE      = INDIRECT("list!Q1:Q" & COUNTA([1]list!#REF!))     ← #REF!
⑤HJ!<T大の定義名>  = INDIRECT("list!B1:B" & COUNTA([1]list!$B:$B))     ← 外部ブック参照
⑤HJ!<K大の定義名> = INDIRECT("list!C1:C" & COUNTA([1]list!$C:$C))     ← 外部ブック参照
```

`VETERAN`/`WAKATE` はどのセルからも参照されていない死んだ名前。`⑤HJ` のシートスコープ名2つは、ブックスコープの同名（正常）を**上書きシャドウ**しているため、`⑤HJ` を使う回には外部ブックが解決できず壊れる可能性がある。

### 9.6 【B】`⑤HN!G11` だけ △ の分岐が抜けている

```
G8  = IF(C8="×","○",IF(C8="○","×",IF(C8="△","△","")))
G9  = 同上
G10 = 同上
G11 = IF(C11="×","○",IF(C11="○","×",""))     ← ★"△" 分岐なし

## 12. 幹事Excel 開発者コメント（2026-09-06・原文ママ）

> HDCP上限についての私のこれまでの計算は女性やシニアに対する優遇は二重にしないというロジックで、よって
>
> ①エブリ◯採用ならHDCP上限等は男性と同じ扱い
>
> ②不採用ならHDCP上限で優遇
>
> の何れかであり両方採用とはしないというロジックでした。

### 12.1 読み解き

幹事Excel が **HDCP上限を男女共通の36** にしている（`score!BM5 = MIN(SUM(AU5:BL5), 36)`）のは、規定文を機械的に実装した結果ではなく、**「女性・シニアへの優遇を二重にしない」という明確な設計意図**によるもの。優遇の手段を2つ（エブリ支給／HDCP上限の緩和）と捉え、**排他**にしている。

| 幹事Excel の運用 | エブリ | HDCP上限 |
|---|---|---|
| ① エブリを採用する場合 | 支給する | **男女共通**（36） |
| ② エブリを採用しない場合 | 支給しない | **性別で優遇**（女性を緩める） |

今回解析したブック（`score!B列` が空＝エブリ未支給）は、この分類では **②に相当するはずだが上限は36のまま**。つまり当該ブックは①の設定で運用されている（＝エブリを使う前提のテンプレートを、エブリなしのコンペにそのまま使った）と解釈できる。**この点は先方に確認する価値がある**（§10.2 の修正提案候補に相当）。

### 12.2 76-Club 側への含意（★重要・candidate A に直結）

76-Club の大学対抗 `uvHdcpA`（`js/calc.js`）は現在:

- HDCP上限 = **男36 / 女40 固定**（規定文 §11.20 準拠）
- エブリ適用 = `g.univ.every` の**オプション**（既定 OFF）

この2つは**独立**しているため、**`g.univ.every` を ON にすると「エブリ支給」と「女性の上限40」が同時に効き、幹事Excel 開発者が明示的に避けている二重優遇の状態になる**。現状はエブリ既定 OFF なので実害は出ていないが、ONにした瞬間に思想が食い違う。

これを踏まえると、取り込み候補 **A（大学対抗のHDCP上限を男女共通36にするオプション）** は、単なる「幹事Excel に合わせる設定」ではなく、**エブリ適用と排他にすべき性質のもの**という位置づけになる。実装するなら以下の3案が考えられる（本書は調査資料であり、どれを採るかは未決）:

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A-1 | `g.univ.capUnified`（男女共通36）を独立したチェックボックスで追加 | 単純・既定OFFで完全互換 | 二重優遇の組合せ（every ON ＋ 女40）を UI で作れてしまう |
| A-2 | **`g.univ.every` が ON のとき自動で上限を男女共通36にする**（連動） | 開発者コメントの思想をそのまま実装＝設定項目が増えない | 「エブリON＋女40」を意図的にやりたい場合に選べない。既存の every ON データの数値が変わる（要 migrate 検討） |
| A-3 | 上限の決め方を3択の select にする（`規定準拠 男36/女40` / `男女共通36` / `エブリと排他（自動）`） | 3つの運用すべてを表現できる | 設定が1つ増える・説明文が要る |

いずれも **§3 計算仕様に触れる load-bearing** で、前後比較が必須。既定は「現行のまま（男36/女40・非連動）」とし、既存コンペの数値を動かさないこと。

### 12.3 個人戦ペリア側との関係

個人戦の `periaHdcp`（PR #118）には **性別による上限差がそもそも無い**（`g.periaCap` は男女共通の1つの値）。よって個人戦側にこの二重優遇の論点は存在しない。女性エブリ（`g.womenEvery.enabled`）と `periaCap` を両方使う運用は可能だが、上限が男女共通なので「優遇が二重」にはならない。**本コメントの影響範囲は大学対抗のみ**。
