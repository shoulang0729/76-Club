## 3. 計算仕様（load-bearing・ここが正）

### 3.1 現行式（`js/calc.js:12`・2026-09-19 時点）

```js
function periaHdcp(g,pid){
  let h=0; g.hidden.forEach((hid,i)=>{ if(hid){ const v=adjHole(g,pid,i);
    if(v!=null) h += g.periaDblPar? Math.min(v, 2*g.par[i]) : v; } });
  let hd=(h*1.5 - parTotal(g))*g.periaCoef;
  const neg = g.periaAllowNeg && g.hidden.every((hid,i)=>!hid || adjHole(g,pid,i)!=null);
  if(hd<0 && !neg)hd=0;
  if(g.periaCap!=null && hd>g.periaCap)hd=g.periaCap;
  return Math.round(hd*10)/10;
}
```

破綻の理由: `h` は **開封済みの隠しホールだけの合計**なのに、`parTotal(g)`(=72) は
**隠し12ホールが全部そろっている前提の定数**。隠しホールが半分しか開いていなければ
`h*1.5` は 72 に遠く届かず、括弧内は負 → `hd=0`。
実測（テストデータ p1・係数0.8・隠しH=1,3,4,5,7,9,10,12,13,14,17,18）:

| 開封 | 開いた隠しH | 6名のHDCP |
|---|---|---|
| 1〜13H | 〜9個 | `0 0 0 0 0 0` |
| 14H | 10個 | `0 0 2.4 0 2.4 2.4` |
| 17H | 11個 | `2.4 0 7.2 0 7.2 7.2` |
| 18H | 12個 | `10.8 0 14.4 7.2 14.4 14.4` |

**1ホールあたり最大変動 12.0打**（18H目・p1/p2/p3 とも同値）。

### 3.2 新式（★本設計の正）

```js
/* ★2026-09-19 暫定HDCP（docs/handoff/2026-09-19-provisional-hdcp.md §3.2）:
   h/k/K/n と「暫定か」の判定はここ1本が正（表示のタグ判定 periaProv も同じものを見る）。
   k=開封(入力)済みの隠しホール数 / K=隠しホール総数 / n=入力済みホール数。
   partial=false（＝18H入力済み、または隠しホールが1つも入っていない）のときは
   下の periaHdcp が 2026-09-19 以前の式と文字どおり同一の経路に落ちる（§3.2 の表）。 */
function periaParts(g,pid){
  let h=0,k=0,K=0;
  g.hidden.forEach((hid,i)=>{ if(hid){ K++; const v=adjHole(g,pid,i);
    if(v!=null){ k++; h += g.periaDblPar? Math.min(v, 2*g.par[i]) : v; } } });
  const n=enteredCount(g,pid);
  return { h, k, K, n, partial: k>0 && (k<K || n<18) };
}
function periaHdcp(g,pid){
  const P=periaParts(g,pid);
  const hEst = (P.k>0 && P.k<P.K) ? P.h*P.K/P.k : P.h;      // ① 隠しホールの平均を K ホール分に引き伸ばす
  let hd=(hEst*1.5 - parTotal(g))*g.periaCoef;
  const neg = g.periaAllowNeg && (P.k>0 || P.K===0);         // ★経過中も負を許す（§3.4）。18H時点の値は不変
  if(hd<0 && !neg)hd=0;
  if(g.periaCap!=null && hd>g.periaCap)hd=g.periaCap;        // ★上限は按分の「前」（§3.7）
  if(P.partial) hd = hd*P.n/18;                              // ② 消化率で按分
  return Math.round(hd*10)/10;
}
/* 表示用（§7）: 1人でも暫定なら true。計算と同じ periaParts を見る＝二重管理を作らない */
function periaProv(g,pids){ return (pids||g.participants).some(pid=>periaParts(g,pid).partial); }
```

**★18H全開で現行と1ビットも変わらないことの証明（構造）**

`partial === false` になるのは次の2通りだけ。

| 状態 | `partial` | `hEst` | `neg` | 按分 | 現行との関係 |
|---|---|---|---|---|---|
| `k===K` かつ `n===18`（＝18H入力済み。K≥1） | `false` | `k<K` が偽 → **`hEst===h`**（ternary の別枝＝浮動小数演算すら通らない） | `k>0` が真 → `allowNeg`。現行の `hidden.every(…!=null)` は「全隠しホールが入力済み」＝`k===K` と**同値** | しない | **式が文字どおり同一** |
| `k===0`（隠しホールを1つも入力していない。K=0 の病的ケース含む） | `false`（`k>0` が偽） | `k>0` が偽 → **`hEst===h===0`** | `K===0` のとき `allowNeg`。現行の `every` は**空配列に対して true** を返すので同値。`k===0 かつ K>0` は両者とも `false` | しない | **式が文字どおり同一** |

すなわち `hEst`・`neg`・cap・丸めの **全分岐が現行と同一のまま**で、`partial` が真のときだけ
末尾に `×n/18` が1つ増える。よって `periaDblPar`／`periaAllowNeg`／`periaCap` の
**どの組合せでも** 18H入力済みの値は変わらない（組合せは式に一切関与しない）。

### 3.4 `periaAllowNeg`（0クリップ解除）との相互作用 ★仕様を1つ緩める

現行の `neg` は「隠し12ホールが**全部入力済み**のときだけ負を許す」（§11.22 D2・経過表示の暴走防止）。

`periaDblPar`ON/`periaAllowNeg`ON/`cap36`・アンダー3名）:

| 開封H | 条件そのまま（`k===K`） | 緩和（`k>0 ‖ K===0`） |
|---|---|---|
| 6H | `0 0 0` | `-5.5 -0.7 -7.9` |
| 12H | `0 0 0` | `-9.9 -4.4 -16.8` |
| 17H | `0 0 0` | `-15.8 -5.9 -24.5` |

条件を緩めても暴走しない理由: 元の「暴走」は *素の* 式で起きる（隠しホールが1つだけ開いた状態で
`h=3` → `(4.5−72)×0.8 = −54` → ネット +54）。新式は **①引き伸ばし** で
`hEst=3×12=36 → (54−72)×0.8 = −14.4` に収まり、さらに **②按分 ×1/18 = −0.8** になる。

`k===K かつ n===18`（K≥1）で `allowNeg`、`K===0` で `allowNeg`、`k===0 かつ K>0` で `false` ＝
**現行 `hidden.every(…)` と完全に同値**。`hdNeg2.mjs` の 1,460 件厳密一致にはこの緩和版も含めて検証済み。

### 3.5 なぜ「消化率で按分」が要るか（ネットの比較可能性）

経過中のグロス（`effGross`）は **n ホールぶんの合計**。ここに 18 ホールぶんの HDCP をそのまま引くと、
「ハンデが大きい選手ほど経過中のネットが実在しない値まで下がる」。按分すると
`net(n) ≒ net(18)×n/18`（ペースが一定のとき）となり、**同じ n の選手どうしの差が最終差の縮小コピー**になる。
これは開封演出（全員が同じ n）で常に成立する。

**途中棄権・入力漏れの選手にも同じ暫定HDCPが付く**（＝保存済みコンペの表示も変わる）。

### 3.8 大学対抗（`uvHdcpA`）★`netScore` を通らない別経路

ユーザー確定は「個人ネット・チーム対抗ネット・大学対抗（平均ネット）すべてに適用」。
うち **大学対抗だけは `netScore` を通らない**（`uvNetA` = `uvGrossA − uvHdcpA`・§11.20 で意図的に独立）。
同じ処方を uv 側にも入れる。uv には `periaAllowNeg` に相当する設定が無い（常に0クリップ）ので
緩和の話は発生しない。**uv 系の関数は §11.20 で意図的に分離されているので、`periaParts` は共有せず
uv 側に同型のローカル変数を置く**（`uvHole` は `uvEvPer` を引くため `H` の値が違う。`k/K/n` は同値になるが、
分離の原則を崩さない）。

```js
function uvHdcpA(g,pid){
  let H=0,k=0,K=0; g.hidden.forEach((hid,i)=>{ if(hid){ K++; const v=uvHole(g,pid,i);
    if(v!=null){ k++; H+=Math.min(v,2*g.par[i]); } } });
  const n=enteredCount(g,pid);
  const partial = k>0 && (k<K || n<18);                  // ★2026-09-19 暫定HDCP（本設計 §3.8）
  const hEst = (k>0 && k<K) ? H*K/k : H;
  let hd=(hEst*1.5 - parTotal(g))*0.8;                   // 係数 0.8 固定（§12 既定事項3・g.periaCoef 非連動）
  if(hd<0)hd=0;
  const p=state.players.find(x=>x.id===pid);
  const cap=(p&&p.gender==='F')?40:36;                   // 規定: 男36/女40（g.periaCap 非連動）
  if(hd>cap)hd=cap;
  if(partial) hd = hd*n/18;
  return Math.round(hd*10)/10;
}
```
