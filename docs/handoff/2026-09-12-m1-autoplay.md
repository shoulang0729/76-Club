## 3. 「勝負が決まるホール」の厳密な定義（R3・★本設計の中核）

### 3.1 一般慣例（根拠）

マッチプレーの決着は「**リード（UP数）が残りホール数を上回った時点**」。例: 残り2ホールで3UP → `3 & 2` で終了。R&A/USGA のマッチプレー規則でも、残りホール数より多くリードした時点でマッチは終了する。リード = 残りホール数（ドーミー）は**まだ決着していない**（残り全部取られれば AS になる）。

### 3.2 このアプリの意味論に翻訳する

このアプリは **18 ホールすべてを集計する**（`m1Result` は早期打ち切りをしない・タイブレークも無い）ため、「決着」は**計算ではなく演出のための概念**である。さらに `m1HoleWin` は **`null`（どちらかが未入力）を返す**ことがあり、`null` のホールは `upA/upB/half` のどれも増やさない ＝ **リード差を絶対に動かせない**。したがって:

> **「残りホール数」は、残っているホールの本数ではなく、残っている“勝敗のつくホール”の本数で数える。**

これを開封順 `k`（0-based）の上で定義する:

```
w[k]   = m1HoleWin(g, a, b, m1HoleAt(k, s))          // 'A' | 'B' | 'H' | null
d(k)   = Σ_{j<=k} ( w[j]==='A' ? +1 : w[j]==='B' ? -1 : 0 )   // k 番目まで開いた時点のリード（正=A）
rem(k) = #{ j : j > k かつ w[j] !== null }            // まだ開いていない“勝敗のつくホール”の本数

determined(k)  ⟺  rem(k) === 0  または  |d(k)| > rem(k)

決定ホール D = determined(k) を満たす最小の k       （w が全部 null のときは D = null）
```

**`rem(k)===0` を OR で足す意味**（これが 18H 決着・AS・未入力打ち切りを1本の式に畳む鍵）:

| ケース | `\|d\|>rem` だけだと | `rem===0` を足すと |
|---|---|---|
| 3&2 で決着 | `k=15` で `\|3\|>2` → **検出** | 同じ（`D=15`） |
| 18H で決着（最終ホールまでもつれる） | `k=17` で `\|1\|>0` → **検出** | 同じ（`D=17`） |
| **AS で終わる** | `d=0` のまま `\|0\|>0` が偽 → **検出できない** | `k` = 最後の勝敗ホールで `rem=0` → **検出**（そのホールが「勝つか AS か」を決めている＝ドラマの本体） |
| **末尾が未入力**（例 15〜18H 空） | 15H 以降が `null` で差が動かないのに、最後まで `rem` が減らず検出が遅れる／AS 同様に落ちる | `k=13`（14H）で `rem=0` → **そこが決定ホール** |

→ **統一的な言い方**: 決定ホール D は「**そのホールを開いた時点で、最終結果（A勝ち / B勝ち / AS）が確定する最初のホール**」。

### 3.3 開封順 `s` に依存することの明示（★重要）

`d(k)` も `rem(k)` も **`w[k]` の並び順**に依存する。`w` は `m1HoleAt(k,s)` で並べ替えられるので、**`D` は `s` の関数**である。§9 の実測では同じスコアで:

- **OUT（`s=1`）… `D=17`**（18ホール目＝18H で決着。0.2秒区間は **0ホール**）
- **IN（`s=10`）… `D=16`**（17ホール目＝**8H** で `2&1` 決着。0.2秒区間は **1ホール**）

**最終結果は `s` に依存しない**（#140 §5.1 の論証・実測。`{upA:8,upB:7,half:3,diff:1}` で一致）が、**演出のヤマ場は `s` で変わる**。これは矛盾ではなく、「実際に回った順で追体験する」という要件そのもの。

### 3.4 ヘルパの仕様と置き場所

**置き場所 = `js/results-m1.js`（演出専用）。`js/calc.js` には置かない。**

| 観点 | `js/calc.js` に置く | **`js/results-m1.js` に置く（採用）** |
|---|---|---|
| 性質 | §3 計算仕様の一部とみなされる（load-bearing） | 表示・演出のみ。集計値・配点に一切使わない |
| `regress.mjs` | ハーネスの読込対象（`calc.js` を vm に load）→ スナップショット管理の対象になる | **対象外**＝期待値ファイルを触らない証明が容易 |
| 受け入れ条件 | `git diff --stat` に `calc.js` が出る | **出ない**（A3） |
| 依存 | — | `m1HoleWin`（純関数）を**読むだけ**。循環依存なし。`index.html` の読込順（calc → results → results-m1）で常に定義済み |

```js
/* 演出専用（§3）: その組の「決定ホール」の開封順 index（0-based）。
   決着 = 残りの“勝敗のつくホール”をすべて相手が取ってもリードを守り切れる（|d|>rem）
          または 残りの“勝敗のつくホール”が 0 本（＝そのホールで最終結果が確定・18H 決着 / AS / 末尾未入力）。
   勝敗のつくホールが 1 本も無い（全ホール未入力）組は null。計算・配点には一切使わない。 */
function m1ClinchAt(g,a,b,s){
  const w=[]; let dec=0;
  for(let k=0;k<18;k++){ const x=m1HoleWin(g,a,b,m1HoleAt(k,s)); w.push(x); if(x!=null) dec++; }
  if(!dec) return null;                       // 1ホールも勝敗がつかない＝ため無し
  let d=0, rem=dec;
  for(let k=0;k<18;k++){
    if(w[k]==='A') d++; else if(w[k]==='B') d--;
    if(w[k]!=null) rem--;                     // rem = k より後ろの“勝敗のつくホール”本数
    if(rem===0 || Math.abs(d)>rem) return k;
  }
  return null;                                // 到達しない（rem は必ず 0 になる）
}
```

- 計算量 18 回 × 組数。tick ごとに呼んでも無視できる（`m1HoleWin` は配列参照2回）。キャッシュしない（キャッシュ無効化のバグのほうが高くつく）。
- **返り値は開封順 index**（実ホール番号ではない）。実ホールに直すのは `m1HoleAt(D,s)+1`。
- **最速の決定ホールは `k=9`（10ホール目）**: `|d| <= k+1` かつ `rem >= 17-k` なので `k+1 > 17-k` すなわち `k >= 9`（＝`10 & 8` が理論上の最速決着）。よって **0.2秒区間は最大8ホール = 1.6秒**（§9 で実測）。

## 4. 自動再生のタイマー設計（R2/R4・★最も事故りやすい）

### 4.1 状態と定数

```js
/* js/nav.js（rl / rlStopTimer と同じ場所・同じ作法。go() と setResGrp/setResGame から呼べる位置に置くため） */
let m1Auto={ key:null, timer:null };     // 自動再生の実行時状態（非保存・揮発。key=再生中の組キー / timer=setTimeout ID）
function m1AutoStop(){ if(m1Auto.timer){ clearTimeout(m1Auto.timer); m1Auto.timer=null; } m1Auto.key=null; }

/* js/results-m1.js */
const M1_AUTO_MS={ step:1000, hold:3000, rest:200 };   // 通常 / ため / 決着後（§6.3 ハードコード＝設定UIなし）
```

- **`setInterval` ではなく `setTimeout` の連鎖**。理由: 間隔が 1000 / 3000 / 200 と可変。`setInterval` では「ため」を表現できない。
- ハンドルは**1本だけ**。`m1Auto.key` が単一なので**同時に2本走ることが構造的にあり得ない**（§4.5）。
- 状態を `js/nav.js` に置くのは **`rl` の前例どおり**（`go()` が `rlStopTimer()` を呼べているのと同じ理由）。読込順は `nav → … → results → results-m1` なので、nav.js の関数本体から results-m1.js の関数を呼ぶことはしない（呼ぶのは逆方向だけ）。

### 4.2 全再描画（`renderResult()`）との共存

**結論: タイマーは DOM 参照を一切保持しない。だから全再描画と無条件に共存できる。**

```
tick → m1Opened.set(key, c+1) → renderResult()（innerHTML 全置換）→ 次の setTimeout を張る
       ↑ 触るのはグローバル状態（Map と key 文字列）だけ。消えた DOM を触らない
```

- ルーレットの `rlTick` は `document.getElementById('rl-name-'+tid)` を毎tick引き直し `if(el)` でガードしている（`js/roulette.js:16-24`）＝**DOM を跨いで保持しない**という同じ規律。本件はそもそも DOM を触らないので、より安全側。
- 副作用として **言語切替・テーマ切替・`render()` の再入**が起きても再生は継続する（`activeTab` が `result` のままなら問題なし）。これは仕様として許容する（§10-9）。

### 4.3 必ず止まる場面（★網羅）

**(a) 明示的な停止点 — 実装必須の 9 箇所**

```js
function m1AutoTick(){

  const g=curGame(), k=m1Auto.key;
  const alive = g && k && activeTab==='result' && resGrp==='team' && resGame.team==='m1'
             && m1RevealMode==='one' && m1Opened.has(k)

  if(!alive){ m1AutoStop(); return; }       // ← 停止点を1つ書き忘れても、最大1tick で必ず止まる
  …
}
```

### 4.4 tick 本体と遅延の決定

```js
/* 次に開くホール（開封順 index j = 現在の開封数 c）を開くまでの待ち時間 */
function m1AutoDelay(g,a,b,s,j,first){
  const D=m1ClinchAt(g,a,b,s);
  if(D!=null && j===D) return M1_AUTO_MS.hold;   // 3000: 決定ホールの「ため」（押下直後でも必ず守る）
  if(D!=null && j>D)   return M1_AUTO_MS.rest;   //  200: 決着後の消化
  return first ? 0 : M1_AUTO_MS.step;            // 1000（押下直後だけ 0＝即反応・§0-13）
}
function m1AutoTick(){ /* §4.3(b) のガード */
  const [a,b]=m1PairOf(m1Auto.key);              // 有効組から引き直す（ガード済みなので必ず存在）
  const s=m1StartOf(g,m1Auto.key);
  const c=Math.min(18,(m1Opened.get(m1Auto.key)||0)+1);
  m1Opened.set(m1Auto.key,c);
  if(c>=18) m1AutoStop();                        // 18 で終了（timer を張らない）
  else m1Auto.timer=setTimeout(m1AutoTick, m1AutoDelay(g,a,b,s,c,false));
  renderResult();                                // 停止状態を反映してから描く（ボタンが ▶再生 に戻る）
}
function m1AutoPlay(k){                          // ▶再生 / ■停止 のトグル
  if(m1Auto.key===k){ m1AutoStop(); renderResult(); return; }   // 走行中の同じ組 → 停止
  m1AutoStop();                                  // ★多重起動防止（rlBeginSpin と同じ作法）
  const g=curGame(); if(!g||m1RevealMode!=='one'||!m1Opened.has(k)) return;
  if((m1Opened.get(k)||0)>=18) return;            // 全開の組は再生しない（ボタンも disabled）
  m1Auto.key=k;
  const [a,b]=m1PairOf(k), s=m1StartOf(g,k), c=m1Opened.get(k)||0;
  m1Auto.timer=setTimeout(m1AutoTick, m1AutoDelay(g,a,b,s,c,true));   // first=true → 通常区間なら即時
  renderResult();                                // 押した瞬間に ■停止 と脈打ちを出す
}
```

- **`first=true` の意味**: 押下直後の 1 ホール目は待たずに開く（反応が見える）。**ただし `j===D` なら 3000 を返す**ので、「幹事が手動で決定ホールの直前まで開けてから再生を押した」場合でも**ためは必ず守られる**。
- **再生開始位置**は「現在の開封数から続行」。0 なら 1 ホール目から、途中なら途中から。「最初から」は既存 `リセット`（c=0）→ 再生の2アクション（§6.2）。
- `m1PairOf(k)` は `m1ValidPairs(g)` から key 一致の組を引く 1 行ヘルパ（`js/results-m1.js`）。

### 4.5 多重起動の防止

| リスク | 対策 |
|---|---|
| 同じ組で2本走る | `m1AutoPlay` 冒頭の `m1AutoStop()`（＝`rlBeginSpin` の `if(rl.timer)clearInterval` と同じ）＋ トグル判定 |
| 複数組で同時に走る | **構造的に不可能**。`m1Auto.key`/`m1Auto.timer` は単数。別カードの再生を押すと前のタイマーが `clearTimeout` される |
| 連打 | 1回目で走行開始 → 2回目は同 key なので停止 → 3回目で再開。常に 0 or 1 本 |
| 再描画中の発火 | tick は同期的に `m1Opened` を更新してから `renderResult()` を呼ぶだけ。再入なし（`renderResult` はタイマーを張らない） |

## 5. 全組一括モード（'all'）との関係

### 5.1 決定：**自動再生は 'one'（一組ずつ）専用**

| 観点 | 'all' で動かした場合 | 'one' 専用（採用） |
|---|---|---|
| 「ため」の成立 | 共通 `revealHoles` 1本で全カードが同時に進む。**組ごとに決定ホールが違う**ので、(i) 全組の決定ホールで止まる → 12組なら**最大12回×3秒＝36秒の停止**が散発し「ため」が日常化して意味を失う／(ii) 最初 or 最後の決着に合わせる → **他の11組にとっては無関係なホールで止まる**。どちらも破綻 | 決定ホールは**その1組のもの**＝要件どおり1回だけ効く |
| 副作用 | `revealHoles` は**スコア表・チーム戦・大学対抗・ベガス・配分タブと共有**。自動で 18 まで進めると **1 on 1 以外の全画面が開封済みになる**（表彰式の進行を壊す） | `m1Opened` は 1 on 1 専用＝副作用ゼロ |
| 投影運用 | 12枚のカードが同時に脈打ち・同時に更新 → 「どこを見ればいいか」が消える（§11.14-1「1画面1主役」に反する） | 1枚だけが動く。司会が実況できる |
| 実装 | 共通バー側に別系統の再生状態が要る（2本目のタイマー） | 既存のカード内バーに1ボタン |

→ **'all' モードでは再生ボタンを描画しない。`m1SetMode('all')` は走行中タイマーを停止する。**

ただし **'all' で開封順（#140）は効く**（#140 §4.4 の決定どおり・共通 `n` を「各組が自分のスタートから n ホール目まで回った」と解釈）。**開封順と自動再生でモードの扱いが違う**点は設計書とヘルプの両方に明記する。

### 5.2 「全組を順番に自動再生」は今回入れない

組1が終わったら自動で組2へ…という連鎖は**入れない**（§16 未決④）。理由: 表彰式では1組終わるごとに司会のコメント・拍手が入るのが普通で、無言で次に進むと**間が潰れる**。幹事が `次の組` → `再生` を押す 2 アクションで十分。

## 6. 幹事の操作（投影運用）

### 6.1 カード内バーのレイアウト（'one' モードのみ・**追加は1ボタンだけ**）

```
現行:  [リセット] [前へ] [次へ] [全開]  (6/18H)
本件:  [リセット] [前へ] [次へ] [全開] [▶再生]  (6/18H)          ← 停止中
       [リセット] [前へ] [次へ] [全開] [■停止]  (7/18H) このホールで決まる   ← 再生中（ため中は右にタグ）
```

| 項目 | 値 |
|---|---|
| クラス | `btn gold sm`（停止中＝`▶`＋`t('m1.play')`） / `btn gray sm`（再生中＝`■`＋`t('m1.pause')`） |
| 配置 | 既存 `.reveal-bar.m1-cardbar` の **`全開` の右・進捗タグの左** |

**`<details>` 折りたたみにはしない**: カード内バーは**再生中に押せる必要がある**（止めたい・巻き戻したい瞬間に開閉操作を挟ませない）。§11.14-3 の要求は「`sm` ボタン・控えめ配置」で、既存バーは既にそれを満たしている（大型 hero の下・`--f-small` 相当）。**新規の設定UIを作らない**ことで原則3をむしろ強く守る。

### 6.2 既存ボタンとの共存（**手動は常に自動に勝つ**）

| 操作 | 自動再生への影響 | 意味 |
|---|---|---|
| `リセット`（c=0） | **停止** | 「最初から」＝リセット→再生の2アクション |
| `前へ`（c-1） | **停止** | 巻き戻して見せ直す |
| `次へ`（c+1） | **停止** | 手送りに切り替える |
| `全開`（c=18） | **停止** | **スキップ＝即全開**（専用ボタンを作らない） |
| `次の組` / `全組オープン` / `すべて伏せる` | **停止** | §4.3(a) #5,6,8 |

→ **専用の「最初から」「スキップ」ボタンは作らない**（既存ボタンが同じ意味を持つ＝ボタン数を増やさない）。

### 6.3 速度は固定（設定UIなし）

`M1_AUTO_MS={step:1000, hold:3000, rest:200}` を `js/results-m1.js` の定数にする。

理由:
1. 要件が具体的な数値を指定している（1.0 / 3.0 / 0.2）。
2. **localStorage キーを増やせない**（load-bearing）ので、可変にすると「毎回設定し直す」か「`golfCompe_v1` に演出設定を書く」（§11.14-4 違反）のどちらかになる。
3. 投影原則3「幹事の操作UIは投影の邪魔をしない」＝スライダー3本を結果画面に出さない。
4. 速度を変えたくなったら **定数1行の変更＋S レーンの Issue** で足りる（設定UIを作るコストより安い）。

§16 未決③に「可変にするか」を既定案（＝しない）付きで残す。

## 9. 数値例（すべて node で実測・裏取り済み）

素点は #140 §6 と同一（実在の人物名・コース名は使わない）:

```
選手B : 5 4 3 5 5 4 3 4 4 | 4 5 4 5 5 3 4 4 5
ホール勝敗 (1H→18H) : A B H A B H B A B | B A A A H B B A A
最終結果 : {upA:8, upB:7, half:3, played:18, diff:+1}  ← s に依存しない（#140 §5.1）
```

### 9.1 決定ホール（★前後比較：開封順で変わる）

| スタート | 決定 index `D` | = 開封 `D+1` 番目 | 実ホール | その時点のリード | 0.2秒区間 |
|---|---|---|---|---|---|
| **OUT (`s=1`)** | **17** | 18 番目 | **18H** | A 1UP | **0 ホール**（存在しない） |
| **IN (`s=10`)** | **16** | 17 番目 | **8H** | A **2UP**（残り1＝`2 & 1`） | **1 ホール**（9H） |
| 参考 `s=7` | 17 | 18 番目 | 6H | A 1UP | 0 ホール |

`s=10` の終盤トレース（`d`=Aのリード・`rem`=残りの勝敗ホール）:

```
k=13  5H w=B d=+2 rem=4
k=14  6H w=H d=+2 rem=3
k=15  7H w=B d=+1 rem=2
k=16  8H w=A d=+2 rem=1   ← |2| > 1 → ★決定（2&1）。この 8H を開ける前に 3.0秒の「ため」
k=17  9H w=B d=+1 rem=0   ← 決着後の消化。0.2秒で開く（最終 diff は +1 のまま＝結果は不変）
```

**要件どおりに読めているかの確認**: IN 組は「8H を開ける瞬間が勝負」。従来（OUT 固定・全手動）ではここが 17 番目の手動クリックでしかなく、**どのクリックがヤマ場かをコードは知らなかった**。本設計はそれを `m1ClinchAt` で機械的に特定する。

### 9.2 タイムライン（秒）

```
IN (s=10) ・ 0 から再生:
 押下 ──[即時]── 10H ─1.0─ 11H ─1.0─ … ─1.0─ 7H ══3.0(ため)══ 8H ─0.2─ 9H ─ 停止
        k=0             k=1        (k=2..15)         k=16          k=17
 合計 = 0 + 1.0×15 + 3.0 + 0.2 = 18.2 秒

OUT (s=1) ・ 0 から再生:
 押下 ──[即時]── 1H ─1.0─ 2H ─ … ─1.0─ 17H ══3.0(ため)══ 18H ─ 停止
 合計 = 0 + 1.0×16 + 3.0 = 19.0 秒（0.2秒区間なし）

早期決着の例（A が 1〜10H を全勝・以降すべて引分）: D=9（10ホール目＝10&8）
 押下 ── 1H ─1.0─ … ─1.0─ 9H ══3.0══ 10H ─0.2─ 11H … ─0.2─ 18H ─ 停止
 合計 = 0 + 1.0×8 + 3.0 + 0.2×8 = 12.6 秒   ← 0.2秒区間は理論上最大 8 ホール（§3.4）
```

### 9.3 未入力が混在する場合（実測）

|---|---|---|
| 15〜18H が未入力（1〜14H のみ入力） | **13**（＝14H・`rem===0` で確定） | 14H の前に 3秒ため → 15〜18H は 0.2秒ずつ空欄が開く（4ホール＝0.8秒）→ 停止 |

| AS で終わる組（`diff===0`） | 最後の勝敗ホール | そのホールの前に 3秒ため（＝「勝つか AS か」が決まる） |

| **①** | **全組一括（'all'）モードでも自動再生を効かせるか** | **効かせない（'one' 専用）** | 'all' は共通 `revealHoles` 1本で全カードが同時に進むため、**組ごとに違う決定ホールの「ため」が原理的に成立しない**（12組なら3秒ためが最大12回散発するか、他組と無関係なホールで止まる）。さらに `revealHoles` はスコア表・チーム戦・配分タブと共有で、自動で進めると**1 on 1 以外まで開封される**。投影でも「1画面1主役」（§11.14-1）に反する。※ **開封順（OUT/IN）は 'all' でも効く**（#140 §4.4）＝挙動が分かれる点だけ要確認 |
| **②** | **18H まで決着しない場合（最終ホール決着 / AS）の「ため」をどこに入れるか** | **最後の“勝敗のつくホール”の前に 3秒**（AS で終わる組も同じ）。ため無しにはしない | そのホールが「勝つか AS か」を決めている＝観客にとってのヤマ場そのもの。式としても `rem===0` で自然に表現でき、**18H 決着・AS・末尾未入力が1本の定義に畳める**（§3.2）。「決着しないなら盛り上げない」を選ぶと、最も多い“18番勝負”のケースで演出が効かなくなる |
| **③** | **速度（1.0 / 3.0 / 0.2秒）を幹事が変えられるようにするか** | **しない（ハードコード定数）** | 要件が数値を明示している／**localStorage キーを増やせない**ので可変にすると毎回設定し直すか演出設定をデータに書く（§11.14-4 違反）ことになる／結果画面にスライダーを出すのは投影原則3 に反する。変更したくなれば**定数1行＋S レーン**で足りる |
| **④** | **1組終わったら自動で次の組へ進む（連鎖再生）を入れるか** | **入れない**（幹事が `次の組` → `再生` の2アクション） | 表彰式では1組ごとに司会コメント・拍手が入る。無言で次に進むと間が潰れる。要望が出れば S〜M レーンで追加可（`m1AutoTick` の終了時に次組へ繋ぐだけ） |
| **⑤** | **「ため」中に「このホールで決まる」と文字で予告してよいか**（ネタバレ感の有無） | **予告する**（脈打ち＋文字タグ） | 3秒の無音は「固まった／ボタンが効いていない」に見え、司会が困る。予告は要件「ためを作る」の目的（観客に構えさせる）そのもの。もし嫌なら**文字タグだけ落として脈打ちを残す**（1行削除で対応可・脈打ちだけでも「次が来る」は伝わる） |
| **⑥**（参考・#140 から引継ぎ） | 列の並べ替え（案Y）／OUT-IN の2択でよいか／配分タブは触らない | **#140 §13 の既定案どおり**（案Y・2択・配分タブ非接触） | モック承認回で①②⑤と一緒に確認する |
