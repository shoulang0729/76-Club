## 4. 計算仕様（§3 系・新設・★load-bearing）

### 4.1 集計対象人数 `uvTargetN(P)`（Q1/Q2 反映・全域定義）

```
uvTargetN(P) = P <= 0 ? 0 : min(P, Math.round(5 + (P − 5) × 0.5))
```

- `P` = 当該校の集計母数（§4.2 の対象メンバー数）。
- 四捨五入は **0.5 → 切上げ**。式の値は P≥1 で常に正（最小は P=1 の 3）なので、JS の `Math.round`（half toward +∞）がそのまま四捨五入と一致する。負値・端数の特殊分岐は不要（P≤0 のみガード）。
- `min(P, …)` が Q2（N は参加者数を超えない）の実装。P≤5 では式の値が常に P 以上になるため、**min だけで「5名以下は全員」も成立**する（下表で確認）。

**例表（P=1〜15）**:

| P（参加） | 5+(P−5)×0.5 | 四捨五入 | N=min(P,·) |
|---:|---:|---:|---:|
| 1 | 3 | 3 | **1** |
| 2 | 3.5 | 4 | **2** |
| 3 | 4 | 4 | **3** |
| 4 | 4.5 | 5 | **4** |
| 5 | 5 | 5 | **5** |
| 6 | 5.5 | 6 | **6** |
| 7 | 6 | 6 | **6** |
| 8 | 6.5 | 7 | **7** |
| 9 | 7 | 7 | **7** |
| 10 | 7.5 | 8 | **8** |
| 11 | 8 | 8 | **8** |
| 12 | 8.5 | 9 | **9** |
| 13 | 9 | 9 | **9** |
| 14 | 9.5 | 10 | **10** |
| 15 | 10 | 10 | **10** |

- 規定の例「参加者14名 → 5+(14−5)×50%=9.5 → 10名」と一致（P=14 の行）。

### 4.2 集計母数と対象者選定

```
uvMembers(g,T) = T.memberIds のうち
  ① g.participants に含まれ ② 選手マスターに実在し ③ 1ホール以上入力済み(entered) の pid
P = |uvMembers(g,T)|、N = uvTargetN(P)
```

- ③（entered）は `teamWinPoints` の対象チーム判定と同型。未入力者を母数に入れると平均が壊れるため、**規定の「参加者数」をアプリ上は「1H以上入力済みの参加メンバー数」と読み替える**（§13 確認事項4・既定として決定）。開封演出中は viewGame のマスク後スコアで判定されるため、開封に応じて自然に成立していく。
- **対象者 = uvMembers を次の順序キーで昇順ソートした先頭 N 名**:
  1. ネット `uvNet`（§4.4・小さい順）
  2. 同ネットは グロス `uvGross`（小さい順）
  3. それも同じなら **`T.memberIds` の登録順**（安定・決定的）
- 境界タイ（N 位と N+1 位が同ネット）もこの順序キーで一意に決まる。個人戦の `tieBreak`（性別→生年月日）は**使わない**（規定に根拠がなく、登録順の方が幹事に説明可能なため）。

### 4.3 学校成績とタイブレーク（Q4 反映）

各校の成績ベクトル（すべて**小さいほど上位**・辞書式に比較）:

```
uvAvg(a)  = Σa / |a|                       // ★Q4 切替ポイント（後述）
r4 = [ uvAvg(対象N名の uvNet),             // ① 対象者の平均ネット（主役）
       uvAvg(対象N名の uvGross),           // ② 対象者の平均グロス
       uvAvg(全員P名の uvNet),             // ③ 全員の平均ネット
       uvAvg(全員P名の uvGross) ]          // ④ 全員の平均グロス
比較用に各成分を Math.round(v×10000)/10000（小数第4位）で丸めて保持。
順位: r4 の辞書式昇順。4成分すべて一致した場合のみ同順位（＝勝ち点は山分け）。
```

- **表示**は小数第2位固定（`toFixed(2)`）。順位判定は比較用4桁丸め値が正（表示丸めで同値に見えても順位が付くことがあり得る・許容）。
- **Q4 切替構造**: 規定の「全員のネットスコア/グロススコア」が**合計**と判明した場合は、③④の組み立て行の `uvAvg(...)` を `Σ(...)` に差し替える**1行変更**で対応する（①②は規定原文が「平均」なので不変）。

### 4.4 ネット定義 `uvNet` / `uvGross`【確定＝案A・独立計算＋エブリ適用オプション】

大会規定準拠の独立計算。エブリはコンペごとのオプション `g.univ.every`（**既定 OFF**）で適用可。

```
uvEvPer(g,pid)  = g.univ.every ? (everyType==='every1' ? 1 : everyType==='every2' ? 2 : 0) : 0
                  // 大学対抗独自のスイッチ。g.womenEvery.enabled（コンペ本体のエブリON/OFF）には連動しない。
                  // 選手ごとの支給量は既存 player.everyType を流用（evPer と同じ判定・enabled ゲートのみ外す）
uvHole(g,pid,i) = 未入力 ? null : 生スコア − uvEvPer(g,pid)   // OFF時は生スコアそのもの
uvGrossA(g,pid) = Σ uvHole(g,pid,i)                     // 入力済みホールの合計
uvHdcpA(g,pid):
  H = Σ_{隠し12H} min(uvHole(g,pid,i), 2×par[i])        // ダブルパーカット（未入力ホールは加算なし）
  hd = (H × 1.5 − parTotal(g)) × 0.8                    // 係数は 0.8 固定（§12 既定事項3）
  hd < 0 → 0
  cap = (player.gender === 'F') ? 40 : 36               // 規定: 男36 / 女40
  hd > cap → cap
  小数第1位に丸め（Math.round(hd×10)/10・既存 periaHdcp と同じ）
uvNetA(g,pid) = uvGrossA − uvHdcpA
uvNet = uvNetA、uvGross = uvGrossA（§4.2/§4.3/§4.5 はこの値を使う）
```

- **ダブルパーカットは隠しホール集計（HDCP算定）にのみ適用**し、グロスはカットしない。一般慣例（ダブルパーカット＝「ハンディキャップに加算できる各ホールスコアの上限がパー×2」・上限クリップは HDCP 値に対して適用）に準拠。出典: [ちきんゴルフ「ダブルペリア方式とは」](https://chicken-golf.com/column/doubleperia-system/)・[きまぐれゴルフ「ダブルペリア（新ペリア）とは」](https://kimagure-golf.com/golf-double-peoria/)。
- 隠しホールは既存 `g.hidden`（12H・§11.1 の Par 配分抽選）を**共用**する。専用の隠しホールは持たない。
- `g.periaCoef`/`g.periaCap` には**連動しない**（独立計算＝規定の大会と同一の値を再現するため。係数 0.8 はダブルペリアの一般慣例）。

**エブリ適用オプションの意味論（追加要件・2026-08-30）**:
- **既定 OFF の根拠**: ①規定原文（§1）にエブリの記載がない＝規定準拠の独立計算にエブリという概念が存在しない。②規定は女性調整を「HDCP上限 40（男36より+4）」として**規定内で既に持っている**ため、エブリを重ねると女性への二重調整になる。③エブリは本アプリ独自のローカル運用（§3.2）であり、大会再現モードでは外すのが素直。→ ローカルコンペで「普段どおりエブリ込みで大学対抗をやりたい」ケースのために ON を用意する。
- **ON 時の適用段階**: **§11.12 H の現行慣例と同一**＝「①エブリを各ホールに先に反映（`uvHole`＝adjHole と同型の −1/−2）→ ②その値でダブルパーカット・隠し12H集計 → ③ネット＝エブリ後グロス − このHDCP」。二重控除にならない（HDCP側はエブリ後基準で小さめに出るだけ）。ダブルパーカットの `min` は**エブリ適用後の値**に対して取る（カット境界もエブリ後で判定）。
- ON は `g.womenEvery.enabled` と**独立**（大学対抗カード内の専用トグル1つで完結。コンペ本体のエブリがOFFでも univ.every ON なら effる／逆も然り）。支給量のみ選手マスターの `everyType` を流用。

**数値例（同一選手・OFF/ON 前後比較）** — 女性・everyType='every1'（各H −1）・18H入力済・パー72:
前提: 生グロス 118。隠し12Hの生スコア合計 92。うち Par4 で 11打・Par3 で 9打（ダブルパー超え候補）。

| 段階 | **OFF（既定）** | **ON（エブリ適用）** |
|---|---|---|
| ホール値 uvHole | 生スコアのまま | 各ホール −1（Par4:11→10・Par3:9→8） |
| Wパーカット | 11→8(−3)・9→6(−3) → 隠し合計 92−6=**86** | 10→8(−2)・8→6(−2) → 隠し合計 (92−12)−4=**76** |
| HDCP | (86×1.5−72)×0.8=45.6 → **女性上限40で 40.0** | (76×1.5−72)×0.8=**33.6**（上限40未満・クリップなし） |
| グロス uvGross | **118** | 118−18=**100** |
| **ネット uvNet** | 118−40.0=**78.0** | 100−33.6=**66.4** |

（同じ数字で男性〔everyType='none'〕なら OFF/ON とも: HDCP 45.6 → 上限36 → ネット 118−36.0=**82.0**）

**参考・不採用案の記録（案B＝現行ネット流用・2026-08-30 不採用）**: `uvNet=netScore / uvGross=effGross` とする案。ゲーム設定の periaCoef/periaCap/エブリがそのまま効き、規定の「上限 男36/女40」「Wパーカット」が再現されないため不採用（上の例の選手なら 隠し=80・HDCP 38.4・ネット 61.6 となり、規定計算 78.0 と大きく乖離）。

### 4.5 学校集計の完全数値例（2校比較・境界タイ・タイブレーク第2段まで）

学校X（参加7名・全員入力済み）: P=7 → N=min(7, round(6))=**6**

| 選手（登録順） | uvGross | uvNet | ネット昇順 | 対象 |
|---|---:|---:|---:|:--:|
| X1 | 82 | 70.2 | 1 | ○ |
| X2 | 85 | 71.0 | 2 | ○ |
| X3 | 90 | 72.4 | 3 | ○ |
| X4 | 88 | 72.6 | 4 | ○ |
| X5 | 93 | 73.2 | 5 | ○ |

### 4.6 勝ち点統合（`teamWinPoints` への組み込み・§11.15/§11.18/§11.19 準拠）

```
uvStanding(g) = { rows:[{ t, P, N, sel(対象pid配列), members(pid配列・ネット順), r4, rank }] }
  // rows は uvMembers が1名以上のチームのみ・r4 辞書式昇順・rank は §4.3

teamWinPoints 内（他種目と同型・add の位置は F.vegas と F.niadoraTeam の間目安）:
if(F.univMatch){ const uv=uvStanding(g);
  if(uv.rows.length>=2) add('univMatch', teams.map(t=>{
    const r=uv.rows.find(x=>x.t.id===t.id); return r? r.rank : null; }), 'asc'); }
```

- `vals` = **順位（1=最良）**を渡す。`add` は最小値のチームを winners にするため、4段タイブレーク済みの順位をそのまま勝ち点判定に使える（完全同点は同 rank → 山分け）。vals は総合タブの表で値表示されない（null=—・勝者=獲得分のみ）ため順位値で問題ない。
- 成立条件 = 対象校（uvMembers≥1）が2校以上（`add` の live<2 ガードと二重でも可）。
- 発表後反映（§11.18）: `g.announced.univMatch` を他種目と同じ連携ボタンでトグル。重み（§11.19）: `points.teamEventPts.univMatch`（既定1）。
- 総合順位→`teamRankPts` 配分は既存のまま（本種目は勝ち点1行が増えるだけ）。

- 選手タブに男女 select 実装済み（`js/players.js` 52行・新規登録 `#pGender`・i18n `player.m`/`player.f`）。既存参照は `tieBreak`（§10.19）とニアドラ2打目の運用注記（§3.6）。
- **womenEvery（エブリ）との関係整理**: エブリ支給量は `player.everyType`（'none'|'every1'|'every2'）で管理され、**gender とは独立の別属性**（§10.1 で性別非連動化済み＝男性にエブリを付けることも、女性に付けないことも可能。calc.js `evPer` は everyType のみ参照）。大学対抗はこの2属性を別の目的で参照する: **gender → HDCP上限（男36/女40）**／**everyType → エブリオプションON時の支給量（−1/−2）**。両者を混同しない（性別からエブリを推定しない・エブリから性別を推定しない）。
- 幹事への影響: 大学対抗を使うコンペでは**選手の性別を正しく登録することが前提**になる（migrate 既定 'M' のままだと女性の上限が36で計算される）。§6.2 の注記（univ.calcNote）とルール解説で明示する。
