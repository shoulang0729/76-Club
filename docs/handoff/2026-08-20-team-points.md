## 3. 計算仕様（正本 §3.5/§3.6 上書き・★load-bearing）

### 3.1 種目リストと採用条件

チーム戦の「種目」は以下。**採用中かつ成立している種目**が各1勝ち点を懸ける（`F = chFormats(g)`＝α/βゲート込み）。

| key | 種目 | 採用条件 | 勝敗値（チームごと） | 向き |
|-----|------|---------|----------------------|------|
| `teamGross` | グロス対抗 | `F.teamGross` | Σ effGross（メンバー） | 小さい方が勝ち |
| `teamNet` | ネット対抗 | `F.teamNet` | Σ net（メンバー・0.1丸め） | 小 |
| `holeByHole` | ホールバイホール | `F.holeByHole` | 取得ホール数 `holesWon()` | 大 |
| `best2ball` | ベスト2ボール（β） | `F.best2ball` | `best2()` | 小 |
| `roulette` | ルーレット対抗 | ルーレット進行あり（`rlStandings(curGame()).won` に >0 あり） | 取得ホール数 | 大 |
| `match1v1` | 1 on 1（β） | `F.match1v1` かつ有効試合に完了(played>0)が1つ以上 | マッチ勝利数（引分は勝利数に入れない） | 大 |
| `vegas` | **ラスベガス（β・★回答で追加）** | `F.vegas` かつ資格チーム（参加メンバーちょうど2人）≥2 かつ 勝ちホール合計≥1 | ベガスの**勝ちホール数**（§3.3.2・点差ではない） | 大 |
| `niadora` | **ニアドラ（新規）** | 他のチーム種目が1つ以上採用中（=チーム戦をやっている）かつ 記録された本数合計≥1 | NP＋DC 獲得本数のチーム合計（§3.3.1） | 大 |

**成立条件（共通）**: 対象チーム（メンバー1人以上・かつメンバーの誰かが1H以上入力済み=`teamEntered`）が**2チーム以上**。1チーム以下なら当該種目は不成立＝勝ち点なし。HBH は取得ホール≥1、ルーレットは決着ホール≥1、ラスベガスは勝ちホール≥1 が追加条件。

- ルーレットには専用の formats トグルがない（現行どおり）。**回した実績があれば自動で1種目**になる。
- ラスベガスの**点差集計（§11.11・ベガス表）は従来どおり独立**（点差そのものは payout に入れない）。勝ち点は §3.3.2 のホール勝敗数のみで決める（D9）。

### 3.2 勝ち点

```
各成立種目につき:
  勝ちチーム = 勝敗値が最良のチーム（3.1 の「向き」）
  勝ちチームに 勝ち点 1
  最良値が同点なら 1/(同点チーム数) ずつ山分け（2チーム同点=各0.5・3チーム同点=各1/3）
チームの総合勝ち点 = Σ（種目の獲得勝ち点）    …… 成立種目数 = 配られる勝ち点の総和
```

### 3.3 新規種目の定義

#### 3.3.1 ニアドラ種目

```
niadoraTeamCount(g, T) =
    Σ_{h ∈ niapinHolesOf(g)} [ prizes.niapinWinner[h] ∈ T.memberIds ]
  + Σ_{h ∈ draconHolesOf(g)} [ prizes.draconWinner[h] ∈ T.memberIds ]
```

- 対象ホールは**パー連動導出のみ**（Par3=NP / Par5=DC・`2026-08-20-npdc-par.md`）。導出対象外ホールに残る勝者記録は**無視**（個人配点と同じ非破壊・可逆規則）。
- どのチームにも属さない勝者（チーム未所属の参加者）の本数は**どのチームにも数えない**（個人配点は従来どおり付く）。
- **個人の niapin/dracon 配点（1本あたり◯pt）は不変**（D5）。同じ1本が「個人◯pt＋チーム種目の本数1」に両方効く＝二重ではなく別枠（個人戦と団体戦）。

#### 3.3.2 ラスベガス種目（ホール勝敗・★ユーザー回答で追加）

**新規計算式は増やさない**。既存 `vegasHoleNet(g,A,B,i)`（§11.11・2桁合体/フリップ/ダブルパー上限込み・正=Aが有利）の**符号を数えるだけ**で勝敗値を作る。

```
資格チーム = vegasPair(g,T) が成立するチーム（参加メンバーちょうど2人・§11.11 のまま）
vegasHoleWins(g):
  総当たり (a,b)（a<b・vegasStandings と同じ回し方）× 各ホール i=0..17 で
    n = vegasHoleNet(g, teams[a], teams[b], i)
    n > 0 → teams[a] の勝ちホール +1
    n < 0 → teams[b] の勝ちホール +1
    n = 0（フリップ適用後も同数字）・null（どちらかのペアに未入力あり）→ どちらにも加算しない
  勝敗値(T) = T の勝ちホール数合計
種目の勝ち = 勝ちホール数が最多のチーム（同数は勝ち点山分け §3.2）
成立      = 資格チーム≥2 かつ 勝ちホール合計≥1
```

- **点差（`vegasStandings` の `tot`）は勝ち点判定に使わない**。1ホールの大差（フリップの大逆転）で点差が負けていても、取ったホール数が多い側が勝ち点1（ユーザー文言「ホールバイホールで勝ったほう」）。点差はベガス表（結果タブのカード）で従来どおり表示・payout 非干渉。
- 同数字ホール（n=0）はどちらの勝ちホールにも数えない（1 on 1 のハーフと同型。2チームなら山分けと等価・3チーム総当たりでも「勝ちのみ加算」で一貫）。
- 3チーム時も総当たりの勝ちホール合計で比較（vegasStandings の総当たりと同じ構造）。

```
順位対象チーム = メンバー1人以上 かつ teamEntered
総合順位      = 総合勝ち点の降順（同点は同順位・次順位は人数分飛ぶ＝1,1,3方式）
各チームの配点 p = points.teamRankPts[順位-1] || 0     （既定 [10,5] → 1位10・2位5・3位0）
チームの各メンバー個人に p を加算（満額・人数割りしない＝D4）
成立種目が 0 のときは配分しない（総合順位自体を出さない）
```

- 総合同点（例 2.5 vs 2.5 vs 0）→ 両者1位で**各員 10pt**、3番目は3位=`teamRankPts[2]`（既定なし=0）。折半はしない（D7。折半にしたい幹事は確認事項 Q3 参照）。
- 勝ち点 0 のチームにも順位はつく（`teamRankPts` を3要素にすれば3位にも配点できる）。
- 賞金配分（`computePayout`）は従来どおり「全員の pt 合計で prizePool を按分」＝変更なし。

### 3.5 数値例（前 → 後の比較・★受け入れ条件）

**例A: 3チーム（R/B/G 各3人）・種目5つ採用（α: グロス対抗・ネット対抗・HBH・ルーレット＋ニアドラ）**

成績: グロス対抗 R261<B265<G270／ネット対抗 R216.2<B218.0<G219.5／HBH B8.5>R6.5>G3.0／ルーレット B5>R3>G1／ニアドラ本数 R3(NP2+DC1)>B2>G1。

| 種目 | 前（現行既定: 勝ちチーム各員 3pt） | 後（勝ち点） |
|------|------|------|
| グロス対抗 | R 各員 +3 | R 勝ち点1 |
| ネット対抗 | R 各員 +3 | R 勝ち点1 |
| HBH | B 各員 +3 | B 勝ち点1 |
| ルーレット | B 各員 +3 | B 勝ち点1 |
| ニアドラ | （チーム種目なし） | R 勝ち点1 |
| **総合勝ち点** | — | **R 3 / B 2 / G 0** |
| **チーム由来の個人pt** | R 各員 6 / B 各員 6 / G 0 | 総合1位 R 各員 **+10**／2位 B 各員 **+5**／3位 G **+0**（teamRankPts=[10,5]） |

- 個人戦分は前後で完全一致: 例 R1 がニアピン2本なら +4pt（niapin=2×2本）は前後とも同額。net/gross の [5,3,1] も不変。
- チーム由来 pt の総和: 前 3pt×2種目×3人×2チーム=36pt → 後 10×3+5×3=45pt（payout の按分比が変わる点に注意）。

**例B: 種目引き分け** — 例Aでネット対抗が R216.2 = B216.2 なら R・B に各0.5 → 総合 R 2.5 / B 2.5 / G 0 → R・B とも**1位で各員 +10**、G は3位 +0。

**例C: 2チーム・β（全8種目: グロス/ネット/HBH/ベスト2/ルーレット/1on1/ラスベガス/ニアドラ）**
- 1 on 1 が 5試合で A 3勝・B 1勝・1分 → 種目 `match1v1` は A に勝ち点1（引分試合は勝利数に不算入）。個人の m1win/m1draw（勝者+2/引分両者+1）は従来どおり別途加算。
- ラスベガス: 18Hのうち A の勝ちホール7・B の勝ちホール5・同数字4・未評価2 → 種目 `vegas` は **A に勝ち点1**。このとき点差合計（ベガス表の `tot`）が仮に B +12 で B 有利でも、勝ち点は**ホール勝敗数基準**（§3.3.2）。点差はベガス表の表示のまま（payout 非干渉）。勝ちホール 6–6 なら各0.5。
- 2チームの総合 2位にも `teamRankPts[1]`（既定5）が配点される（勝者総取りにしたい幹事は `teamRankPts` を「10」1要素に設定）。

### 3.6 不変範囲（load-bearing）

- 個人配点全て: `net/gross/stableford/olympic/callaway/nassauTotal`（配列）・`niapin/dracon`（1本あたり）・`m1win/m1draw`（1 on 1 個人）— **computePoints の該当ブロックは無変更**。

- ラスベガスの**計算関数**（`vegasHoleNet`/`vegasStandings`/`vegasPair` — 一切変更しない。勝ち点は `vegasHoleNet` の符号を**読むだけ**）と点差の独立集計・ベガス表表示（§11.11。点差は引き続き payout 非干渉）。
- `computePayout` の按分式・`nextKanji`・localStorage キー・表示状態分離。

## 5. 実装ガイド（js/calc.js・関数設計）

新規は純粋関数3つ＋computePoints のチームブロック置換のみ。

```js
// §3.3.1 ニアドラ本数（チーム合計）
function niadoraTeamCount(g, T){ /* niapinHolesOf/draconHolesOf × winner ∈ T.memberIds を数える */ }

// §3.3.2 ベガス勝ちホール数。vegasStandings と同じ総当たりで vegasHoleNet の符号のみ数える
//   返り値 { teams, wins:number[] }（teams=資格チーム＝vegasPair 成立チーム）
function vegasHoleWins(g){ /* n>0→a勝ちホール+1 / n<0→b+1 / 0・null→加算なし */ }

// §3.1〜3.2 種目別勝ち点。返り値 { teams, wins:number[], events:[{key, winners:int[], vals:(number|null)[]}] }
//   teams = 順位対象チーム（memberIds≥1 かつ teamEntered）。teams.length<2 なら events=[]
//   vals[i]=null はその種目の対象外チーム。winners は teams の index。突合は team.id で行う
//   （viewGame は g を Object.assign コピーするが teams 配列の要素は同一参照。ただし rlStandings/holesWon
//    は独自に g.teams をフィルタするため index 前提にせず id 突合を必須とする）
function teamWinPoints(g){ ... }
```

- `computePoints` の現行チームブロック（calc.js:158-174 `awardTeam`〜roulette）を**丸ごと置換**:
  ```js
  if(g.teams.length){
    const {teams,wins,events}=teamWinPoints(g);
    if(events.length){
      const rows=teams.map((t,i)=>({t,v:wins[i]})); rows.sort((a,b)=>b.v-a.v);
      let rank=0,prev=null;
      rows.forEach((r,i)=>{ if(prev===null||r.v!==prev){rank=i+1;prev=r.v;}
        const p=(P.teamRankPts||[])[rank-1]||0;
        r.t.memberIds.forEach(pid=>{ if(pts[pid]!=null)pts[pid]+=p; }); });
    }
  }
  ```
- ルーレットは現行どおり `curGame()`（実ゲーム）基準・他種目は渡された `g`（viewGame マスク反映）基準。1 on 1 は `m1ValidPairs(g)`×`m1Result(g,…)`（個人配点ブロックと同じ入力）。ラスベガスは `vegasHoleWins(g)`（viewGame 基準＝未開封ホールは null で自動スキップ）。
- `teamWinPoints` は表示（§6）とも共用する（結果タブの種目別勝ち点表・総合順位はこの1関数だけを正とする）。
