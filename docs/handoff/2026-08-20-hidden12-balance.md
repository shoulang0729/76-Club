## 0. ユーザー報告（原文・2026-08-29）

> コース設定の隠しランダムホール設定が間違っている。前半後半でパー３、パー５、パー４ ２ホールずつ、偏りがあってはならない

解釈（本設計で確定）: 隠し12ホールは **前半(1-9H)から6・後半(10-18H)から6** を選び、**各半分の内訳を Par3×2・Par5×2・Par4×2**（2+2+2=6）とする。全体では Par3×4・Par5×4・Par4×4 ＝ 12ホール。

## 1. 現行の問題点（何が間違っていたか）

現行 `randomHidden()`（js/course.js:31-36、§11.1 準拠）:

- 全18ホールを Par3/Par4/Par5 に分類し、**全体から** Par3×2・Par4×8・Par5×2 を無作為抽選。
- **前半/後半の制約がない**。例: Par4 を10個から8個取るため、前半の Par4×5 が全部選ばれ得る → 最悪 **前半9ホール全部が隠し・後半3ホールのみ** という偏りが発生する（Par3×2前半＋Par5×2前半＋Par4前半5全部＝9）。
- 帯別の枚数も報告ルールと不一致: 現行は Par4×8（Par3/Par5 は各2＝18ホール中の半分だけ）。報告ルールは Par4×4・Par3×4・Par5×4。

`seedTestData()`（js/testdata.js:19-20）はさらに緩く、**パー帯の制約すらない**全18から12の無作為抽選（`randomHidden` 未使用）。

なお隠しPar合計は現行 3×2+4×8+5×2=48、新ルールも標準コースで 3×4+4×4+5×4=48 で**不変**（ペリアHDCPの `-72` 基準は崩れない）。

## 2. 新アルゴリズム【確定＝帯配分／設計案＝関数化・フォールバック】

### 2.1 共通純関数 `pickHidden12(par)` を course.js に新設【設計案】


- グローバル関数（非ESM・従来どおり `<script src>` 読込）。course.js は testdata.js より先に読み込まれる（state→…→course→score→testdata→…）ため参照可。

### 2.2 抽選手順（各半分ごとに独立実行）

前半 = index 0..8、後半 = index 9..17。各半分について:

1. **帯分類**: `par===3 → P3`、`par===4 → P4`、`par>=5 → P5`（Par6 は P5 扱い＝現行踏襲）、`par<3`（0=未設定・異常値）→ `U`。
   - ※現行実装は `p<=3` を P3 に入れており par=0 がショート扱いになるバグ含み。新実装では U に分離する。
2. **層化抽選**: P3 から `min(2, |P3|)`、P5 から `min(2, |P5|)`、P4 から `min(2, |P4|)` を無作為抽選。
3. **補充**: 選抜数が6未満なら、不足分を同じ半分の残余から **P4残 → P5残 → P3残 → U** の優先順で無作為補充し、必ず6にする（各半9ホール固定なので6は常に確保できる）。
4. **超過なし**: 各帯 `min(2, n)` で切るため超過は発生しない（帯に3以上あっても2まで）。

両半分の結果を合成して boolean[18] を返す。**合計12・各半6 は無条件に成立**する（18ホール固定のため破綻ケースなし）。

## R1. なぜ変えるか（2026-09-11 実測・n=50,000／`Math.random()`）

## R2. 新ルールの定義【確定】

### R2.1 帯配分（各半分＝1-9H / 10-18H で独立に実行）

1. **帯分類（rev.1 から不変）**: `par===3 → P3` ／ `par===4 → P4` ／ `par>=5 → P5`（**Par6 は P5 帯**）／ `par<3`（0＝未設定・異常値）→ `U`。
2. **層化抽選（rev.2 で変更）**: P3 から `min(1,|P3|)`、P5 から `min(1,|P5|)`、P4 から `min(4,|P4|)`。基本形 **1+1+4＝6**。
3. **補充（rev.1 の順を踏襲）**: 6 未満なら同じ半分の残余から **P4残 → P5残 → P3残 → U** の順に無作為補充して必ず 6 にする。
   - 踏襲の根拠: 不足は「その帯が枯れた」ときにしか起きず、隠しPar合計を基準値（各半24）に最も近く保てるのは中間帯 P4 の残余。実測でも P3 が 0 の半分で合計 25（＝理論上の最小ズレ +1。P3 が無い以上 24 は作れない）。
4. **超過なし**: 各帯 `min(quota, n)` で切るため、帯に何ホールあっても quota を超えない。

両半分を合成して boolean[18]。**合計12・各半6 は無条件に成立**（各半9ホールなので6は常に確保できる）。ランダムな par 配列 30万通りの総当たりファズで **true≠12 / 前半≠6 は 0 件**を確認済み（2026-09-11 実測）。

### R2.2 Par4 帯内は**一様**にする（シャッフルを Fisher–Yates に差し替える）【確定】

現行実装のシャッフルは `arr.slice().sort(()=>Math.random()-0.5)` で、比較子が非推移的なため**一様でない**。旧ルールでは 5→2 で 48%/45%/33%/45%/28%（理想は一律40%）のズレだったが、新ルールの 5→4 では**ズレが拡大する**（実測 74%/93%/79%/81%/72%、理想は一律80%）。2H だけ 93%・8H は 72% と 21pt 差になり、「Par4 のどれが隠れるか」が事実上固定されるホールが出る。

→ **Fisher–Yates 一様シャッフルに差し替える**（実測: 80.4/79.8/80.1/79.9/79.8 ＝ 一律80%。除外される Par4 の5通りも 19.98/20.03/20.12/19.91/19.97% とほぼ均等）。これは**新ルール成立の必須条件**（「Par4 内は均等であるべき」と判断した）。

### R2.3 実装イメージ（`js/course.js` の `pickHidden12` 差し替え。実装者はこの形でよい）

```js
function pickHidden12(par){
  const shuf=a=>{ a=a.slice(); for(let i=a.length-1;i>0;i--){ const j=Math.floor(Math.random()*(i+1)); [a[i],a[j]]=[a[j],a[i]]; } return a; };
  const pick=(arr,n)=>shuf(arr).slice(0,Math.max(0,n));
  const hidden=Array(18).fill(false);
  [0,9].forEach(s=>{
    const p3=[],p4=[],p5=[],u=[];
    for(let i=s;i<s+9;i++){ const p=par[i]; (p===3?p3:p===4?p4:p>=5?p5:u).push(i); }
    const sel=[...pick(p3,Math.min(1,p3.length)), ...pick(p5,Math.min(1,p5.length)), ...pick(p4,Math.min(4,p4.length))];
    [p4,p5,p3,u].forEach(grp=>{ pick(grp,grp.length).forEach(i=>{ if(sel.length<6 && !sel.includes(i)) sel.push(i); }); });
    sel.forEach(i=>hidden[i]=true);
  });
  return hidden;
}
```

差分は実質 **(a) `Math.min(2,...)` → `1/1/4`** と **(b) シャッフルの一様化** の2点のみ。関数シグネチャ・呼び出し元（`randomHidden`）・行頭コメントの更新以外は触らない（コメントは rev.2 の内容に書き換えること）。
