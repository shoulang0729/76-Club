# 隠し12ホール抽選の前後半×パー帯 均等化（hidden12-balance）

- 日付: 2026-08-29（ファイル名の日付は投影原則期の連番に合わせ 2026-08-20 系列）
- 種別: バグ修正（ユーザー報告）
- 対象: `js/course.js`（`randomHidden`）・`js/testdata.js`（`seedTestData` の hidden 生成）
- **正本との関係: 本ファイルは 2026-07-12-golf-compe-web.md §11.1【確定・Issue#2】の抽選規則を上書きする**（§11.1 側の「非標準フォールバック」「受け入れ条件」も本ファイル §3/§5 が正）。
- **§3 計算仕様には非接触**: ダブルペリアの計算式（`periaHdcp` ＝ エブリ適用後スコア `adjHole` 基準の隠し12合計 → §11.12 H）は一切変更しない。変わるのは `g.hidden[18]` の**選び方（true の立て方）だけ**。`g.hidden` のデータ形式（boolean[18]・12個 true）・localStorage スキーマ（`golfCompe_v1`）は不変。

## 0. ユーザー報告（原文・2026-08-29）

> コース設定の隠しランダムホール設定が間違っている。前半後半でパー３、パー５、パー４ ２ホールずつ、偏りがあってはならない

解釈（本設計で確定）: 隠し12ホールは **前半(1-9H)から6・後半(10-18H)から6** を選び、**各半分の内訳を Par3×2・Par5×2・Par4×2**（2+2+2=6）とする。全体では Par3×4・Par5×4・Par4×4 ＝ 12ホール。

## 1. 現行の問題点（何が間違っていたか）

現行 `randomHidden()`（js/course.js:31-36、§11.1 準拠）:

- 全18ホールを Par3/Par4/Par5 に分類し、**全体から** Par3×2・Par4×8・Par5×2 を無作為抽選。
- **前半/後半の制約がない**。例: Par4 を10個から8個取るため、前半の Par4×5 が全部選ばれ得る → 最悪 **前半9ホール全部が隠し・後半3ホールのみ** という偏りが発生する（Par3×2前半＋Par5×2前半＋Par4前半5全部＝9）。
- 帯別の枚数も報告ルールと不一致: 現行は Par4×8（Par3/Par5 は各2＝18ホール中の半分だけ）。報告ルールは Par4×4・Par3×4・Par5×4。

`seedTestData()`（js/testdata.js:19-20）はさらに緩く、**パー帯の制約すらない**全18から12の無作為抽選（`randomHidden` 未使用）。

なお隠しPar合計は現行 3×2+4×8+5×2=48、新ルールも標準コースで 3×4+4×4+5×4=48 で**不変**（ペリアHDCPの `-72` 基準は崩れない）。

## 2. 新アルゴリズム【確定＝帯配分／設計案＝関数化・フォールバック】

### 2.1 共通純関数 `pickHidden12(par)` を course.js に新設【設計案】

```
pickHidden12(par: number[18]) → boolean[18]   // true が常にちょうど12個
```

- グローバル関数（非ESM・従来どおり `<script src>` 読込）。course.js は testdata.js より先に読み込まれる（state→…→course→score→testdata→…）ため参照可。
- `randomHidden()` は `g.hidden = pickHidden12(g.par); save(); renderCourse();` に簡素化。
- `seedTestData()` の hidden 生成（testdata.js:19-20 の独自抽選）も `g.hidden = pickHidden12(g.par);` に置換（テストデータにも同ルール適用）。

### 2.2 抽選手順（各半分ごとに独立実行）

前半 = index 0..8、後半 = index 9..17。各半分について:

1. **帯分類**: `par===3 → P3`、`par===4 → P4`、`par>=5 → P5`（Par6 は P5 扱い＝現行踏襲）、`par<3`（0=未設定・異常値）→ `U`。
   - ※現行実装は `p<=3` を P3 に入れており par=0 がショート扱いになるバグ含み。新実装では U に分離する。
2. **層化抽選**: P3 から `min(2, |P3|)`、P5 から `min(2, |P5|)`、P4 から `min(2, |P4|)` を無作為抽選。
3. **補充**: 選抜数が6未満なら、不足分を同じ半分の残余から **P4残 → P5残 → P3残 → U** の優先順で無作為補充し、必ず6にする（各半9ホール固定なので6は常に確保できる）。
4. **超過なし**: 各帯 `min(2, n)` で切るため超過は発生しない（帯に3以上あっても2まで）。

両半分の結果を合成して boolean[18] を返す。**合計12・各半6 は無条件に成立**する（18ホール固定のため破綻ケースなし）。

### 2.3 フォールバック判定表（半分単位）

| その半分の構成 | P3採用 | P5採用 | P4採用 | 補充 | 結果6ホール |
|---|---|---|---|---|---|
| 標準: P3×2, P4×5, P5×2 | 2（全） | 2（全） | 5から2抽選 | なし | 3,3,5,5,4,4 |
| P3×3, P4×4, P5×2 | 3から2抽選 | 2（全） | 4から2抽選 | なし | 3,3,5,5,4,4 |
| P3×2, P4×6, P5×1 | 2（全） | 1（全） | 6から2抽選 | P4残から1 | 3,3,5,4,4,4 |
| P3×1, P4×6, P5×2 | 1（全） | 2（全） | 6から2抽選 | P4残から1 | 3,5,5,4,4,4 |
| P3×2, P4×3, P5×2, U×2 | 2 | 2 | 3から2 | なし（6充足） | 3,3,5,5,4,4 |
| P3×0, P4×2, P5×0, U×7 | 0 | 0 | 2（全） | P4残0→P5残0→P3残0→**Uから4** | 4,4,U,U,U,U |
| 全ホール par 未設定（U×9） | 0 | 0 | 0 | Uから6 | U×6 |

補充順の根拠: 隠しPar合計を48（=各半24）に最も近づけるのは中間帯 P4 の残余（§11.1 の旧補充順「ミドル→ロング→ショート」を踏襲し、未設定 U を最後尾に追加）。

### 2.4 抽選例（前後比較）

**例1・標準コース**（testdata.js の par ＝ `[4,4,3,5,4,4,3,4,5, 4,4,3,4,5,4,4,3,5]`）
- 旧: 例えば `{3H,7H, 1H,2H,5H,6H,8H,10H,11H,15H, 4H,9H}` → 前半8・後半4 の偏りが起こり得た（Par帯は 2/8/2 だが半分バランスなし）。
- 新: Par3（3H,7H,12H,17H）と Par5（4H,9H,14H,18H）は**全て必ず隠し**。Par4 は前半 {1H,2H,5H,6H,8H} から2・後半 {10H,11H,13H,15H,16H} から2 を抽選。例: `{3H,7H,4H,9H,1H,6H | 12H,17H,14H,18H,10H,15H}` ＝ 各半6・隠しPar合計48。

**例2・非標準**（前半が Par3×3: par ＝ `[4,3,3,5,4,4,3,4,5, ...]` 前半計35）
- 前半: P3={2H,3H,7H} から2（例 2H,7H）、P5={4H,9H} 全2、P4={1H,5H,6H,8H} から2（例 5H,8H）→ `{2H,7H,4H,9H,5H,8H}`。Par3 の1つ（3H）は隠しに入らない。前半隠しPar合計 = 3+3+5+5+4+4 = 24。
- 後半: 標準どおり。

## 3. 変えないもの

- **手動トグル `toggleHidden`**: 従来どおり完全自由（均等ルールはランダムボタンのみ）。`clearHidden`・`hidCount`・`hiddenNote` の12カウント表示・`courseGrid` の黄色枠表示（`.hidden-h`）はすべて不変。
- **§3 計算**: `calc.js` は `g.hidden.forEach((hid,i)=>{ if(hid){ adjHole(...) } })` で boolean[18] を読むのみ → 形式一致・非接触。`node tools/verify.mjs` の計算回帰（#3・Vegas）にも影響なし。
- **i18n**: 変更なし。`game.random12`（隠し12ランダム）・`game.hiddenNote` は現文言のまま（抽選ルールの注記追加は今回見送り。i18n.js はドロワー化作業と競合中のため非接触が安全。必要なら別 Issue）。
- **localStorage / データモデル（§4）**: 非接触。

## 5. 受け入れ条件

1. 標準コース（par72・各半 Par3×2/Par4×5/Par5×2）で「隠し12ランダム」を実行すると、**毎回** 前半6・後半6、各半の内訳 Par3×2・Par5×2・Par4×2、合計12、隠しPar合計48 になる。
2. 連打すると Par4 の選抜ホールが変わる（Par3/Par5 は標準コースでは毎回全ホール選出＝仕様どおり）。
3. 非標準コース（例2 の Par3×3 前半）で §2.3 の判定表どおりになり、いかなる par 配列（全0含む）でも例外なく true がちょうど12個・各半6個。
4. `seedTestData()` 生成ゲームの hidden も同ルールで各半6・帯均等になる。
5. 手動チェックボックス（toggleHidden）は従来どおり自由に付け外しでき、カウント表示も従来どおり。
6. `node tools/verify.mjs` が green（i18n パリティ・計算回帰とも変化なし）。
7. `g.hidden` は boolean[18] のまま（localStorage の既存データ互換）。
