## 1. 保存データ契約（実装者間で共通）

```js
g.match1v1.pairs = [ ['a','b'], ['a',['b','c']], [['a','d'],'b'] ];
// side = string pid | [string pid, string pid]。配列は必ず2名。
g.match1v1.starts = {}; // 既存の試合キー → 開始ホール1..18
g.univ = { every: false, capMode: 'standard' }; // capMode: standard | common36
g.honestJohn = { hidden: Array(18).fill(false), declarations: {} };
// hidden は長さ18の boolean 配列。declarations は pid → 有限・非負の number。
g.formats.honestJohn = false;
g.announced.honestJohn = false; // 未定義も false。発表・総合連携の保存フラグ。
g.points.teamEventPts.honestJohn = 1;
```

- `hidden` は0始まり添字、ちょうど4個 true が成立条件。DP12 の `g.hidden` と独立し、参照共有もしない。
- 仮想選手を `state.players`／`participants`／`scores` に作らない。複合サイドはマッチの計算・表示に限る値。
- 複合かどうかは pair のいずれかの side が配列かで判定。個人配点を制御する別の保存フラグは不要。
- `newGame` と `migrate` に上記既定を明記。既存 `univ.every`・宣言・選択・重みを上書きしない。
- 既存データに無い `univ.capMode` は `standard`。未知値は既定扱いにして既存結果を守る。
- `honestJohn`／そのフィールド自体が無ければ補完。既にある malformed な hidden 配列を勝手に4穴へ修復しない。
- バックアップ import は同じ migrate を通す。export/import 往復で新設定・複合 pair・starts を保存する。
- localStorage キー、従来の string/string pair、表示状態の保存先は変更しない。

## 2. 複合サイドのマッチプレー

### 2.1 有効性・識別・操作

- side は空でない pid 文字列または長さ2の pid 文字列配列のみ。空配列・1名配列・3名以上・nested 配列は無効。
- 同一 side 内の重複、左右に同じ pid、同一 teamA/teamB、非参加者・不存在ID・反対側所属を拒否する。
- 有効性は現在の `teamMembers(g,T)` と対戦対象2チームから判定。無効保存データは警告し、計算対象から外す。
- 同一試合の重複登録も拒否する。別試合での同一選手の再登場は既存の人数差運用のため許容する。
- side 内の順序で試合識別を変えない。複合キーは `m1@` + `encodeURIComponent(JSON.stringify([sortedSideA,sortedSideB]))` とし、区切り文字連結の衝突を避ける。
- string/string の `m1Key(a,b)` は既存 `a + ':' + b` を保持し、過去の starts を読めるようにする。
- 比較・重複検出・starts・開封・自動再生は同じ共有キー関数を使う。表示名をキーにしない。
- 既存編集カードに各 side の第2選手（なし可）を追加。登録済みの編集・追加・削除・順序移動・開始ホール指定すべてを対応。
- pair 編集では開始ホールを新キーへ移し、旧 starts と旧開封状態を消す。順序移動ではキー・開始ホールを保つ。
- 削除／全消去／選手の完全削除では該当 pair と starts を除去する。片側を自動で1名へ縮めない。
- 一時的な参加解除・所属変更では既存の可逆運用を保ち、無効組として表示する。

### 2.2 計算と配点

- ホールごとに各実選手の `adjHole`（every 適用後）を取り、side 内の算術平均を比較する。丸めない。
- 比較は `sumA * countB` と `sumB * countA`。少ない側が1UP、同値は half。
- そのホールで1人でも未入力／未開封なら両 side ともそのホールを集計しない。人数を減らして平均しない。
- 例：単独5、相手2名4・5なら平均4.5で複合側の勝ち。四捨五入5にして half としない。
- 例：単独5、相手実打6・6で片方 every1 なら `(5+6)/2=5.5`、単独側の勝ち。
- `m1Result` の `{upA,upB,half,played,diff}`、途中結果・AS・勝利数によるチーム判定は従来と同じ。
- **複合試合の個人 m1 配点は全員0**。複合側2名にも単独の相手にも win/draw を加えない。山分けしない。
- string/string 試合は従来の `m1win`／`m1draw` を保持。同じゲームに混在しても試合単位で判定する。
- チーム種目としての勝利数と、総合チーム順位による全員への配点は従来どおり。個人 m1 加算とは別。

### 2.3 表示・関連経路

- ヒーローは実名を「＋」で並べ、複合側に平均の明示。各実選手と平均を確認できるホール明細を提供。
- 投影の既存フォント・折り返し・勝ち/half 表示を使い、個人配点対象外を複合試合に明示する。
- 組別開封、全部開封、OUT/IN/任意開始、自動再生の勝敗/決着演出は平均判定を共通利用する。
- 未開封値を生の g から表示しない。名前等のHTMLは `esc`、inline handler のキーも安全に渡す。
- 選手参照件数・監査・完全削除は side を展開。`sheet-model` の出力は両名と平均を表現し、配列を pid として検索しない。

## 3. 大学対抗の上限選択

- `standard`：男性36／女性40（現行）。`common36`：男女共通36。大学対抗専用の `uvHdcpA` 上限だけ変更。
- every 適用、Wパーカット、係数0.8、暫定HDCP按分、対象人数・4段の順位判定は既存仕様を維持。
- `univ.every` と capMode は独立。従来 `standard + every ON` の保存データを禁止／自動変更しない。
- 例：18H、上限前HDCP45.6・実効グロス118の女性は standard で40/ネット78、common36 で36/ネット82。男性は両方36/82。
- 設定に2択を追加し、ルール解説・設定注記・結果注記・出力モデルが現在の上限と every ON/OFF を正しく説明する。
- 固定の「女性上限40」説明を common36 に残さない。`setUniv` は capMode を boolean 化せず文字列として検証する。
- 一般ネット種目の `periaCap`／`periaCoef`／`womenEvery` は変更しない。

## 4. オネストジョン（first-class team event）

### 4.1 計算

- 対象チームは実在参加メンバーが1名以上のチーム。スコア入力の有無で対象チーム／対象者を絞らない。
- 各チームの全 `teamMembers(g,T)` を集計する。チーム未所属者はチーム合計に含めない。
- 成立には対象チーム2以上、正しい hidden18/選択4穴、対象全員の宣言と生スコア18Hが必要。
- raw スコアは数値として有限であること。空文字・null・欠損・NaN 等は未完了。置換穴にも元スコア入力が必要。
- 宣言は18Hの申告合計。空入力は削除して未申告に戻す（0に変換しない）。不正な数値は拒否する。
- `gross = sum(raw18)`、`actual = gross - sum(raw[hidden4]) + sum(par[hidden4])`。
- `delta = actual - declared`、`penalty = delta > 0 ? delta*10 : delta < 0 ? -delta*30 : 0`。
- every・DP HDCP・Wパーカット・一般ネットは一切使わない。選択穴の par が不正なら不成立。
- 例：raw合計100、選択4穴の実打計25、par計16なら actual=91。宣言90→+1/10点、宣言92→−1/30点、宣言91→0点。
- チーム値＝全員の penalty 合計（平均にしない）。例 A=10+30=40、B=0+50=50なら A が勝ち。
- 最小合計のチームに既定1勝ち点。2チーム同点は0.5ずつ、一般に `weight / 同点チーム数`。
- 個人 penalty は判定明細であり個人ポイントに直接加減しない。総合チーム順位配点は既存方式を使う。
- 不足者を除外して暫定勝者を出さない。1人／1チームでも不足なら種目全体 pending、勝者・点数算入なし。
- 共通ヘルパー `hjStanding(g)` の rows は `{t,members:[hjPlayer結果],ready,total:null|number,rank:null|number}`。データreadyは対象1チーム以上かつ全員完了でよく、種目成立の2チーム条件は呼出側が追加する。

### 4.2 操作・開封・発表

- 採用トグル、種目別重み、チーム種目認識、結果の既存下段タブ、総合勝ち点表に `honestJohn` を追加（α/β共通）。
- ゲーム設定に専用18穴セレクタ・選択数・ランダム4穴ボタンを配置。DP12 抽選とは完全分離。
- ランダムは18穴から重複なし4穴、par配分制約なし。手動選択時の4穴不足／超過を明示し、計算は必ず検証する。
- ゲーム設定の同じ専用カード内で参加者別の宣言を編集。完全削除では宣言も削除し、監査は不存在参照を検出する。
- 結果はチーム名・合計penaltyを大型表示し、明細は氏名／宣言／raw gross／置換後actual／差／penalty。
- 結果画面に不足条件と不足選手を表示。準備完了前は発表を無効化し、保存済み announced=true でも不成立なら点を与えない。
- 専用結果は生ゲームを使い、`announced.honestJohn` の発表操作を明細開示・総合連携の共通ゲートにする。既存の全競技共通 `revealHoles` には依存させない。
- ポイント画面が部分開封のビューを使う場合もHJだけは生ゲームを参照する。ビュー元は揮発WeakMapで保持し、他競技のマスクやJSON保存には影響させない。
- 未発表は総合・明細・出力の勝敗/合計/penalty をマスクする。発表が生スコア明細の明示的な開示となる。
- 保存するのは announced。発表取消で総合算入・公開結果を戻せる。宣言・隠しホール編集時は発表を取り消す。
- 出力モデルに独立した種目明細を追加し、未発表・不足時に未マスク結果を出さない。形式OFFなら既存出力と同じ。

### 4.3 承認済みの列開示・4穴ルーレット（2026-11-17追補・4.2の一括開示を置換）

- モック `/workspace/output/honest-john-ui-mock.png` を提示し、ユーザー回答「名前はフルネームでよろしく」を反映。表は全員のフルネームを省略せず、チーム登録順・メンバー登録順で表示する。
- 数値5列（申告・実打合計・4穴換算後・差・ペナルティ）に個別の開く/閉じる操作を置く。開示フラグはゲームオブジェクトごとの揮発WeakMapに保持し、保存・帳票へ混入させない。再読込では全列を伏せる。
- 申告・実打は抽選前も個別に開ける。換算後・差・ペナルティは4穴と全対象者の入力完了後のみ開ける。閉じた値はHTML属性やaria-labelにも埋めない。
- チーム合計・順位・勝者色は、成立・発表済み・ペナルティ列開示の全条件まで伏せる。発表操作はペナルティ列開示後のみ可能。帳票は従来どおり発表済みかつ成立を条件にする。
- 「状態」はスコア表から取り除き、表と抽選の下の閉じた幹事用details内にフルネームと入力不足を列挙する。全員の準備状況も主役のヒーローへ出さない。
- 表の直下に横4枠の抽選を配置。START→STOPで1穴ずつ確定、候補は未選択の18穴のみ。4穴確定で停止。STOP連打による複数確定や重複を防ぐ。
- 確定穴だけ既存hidden:boolean[18]に保存し、回転候補・タイマー・抽選順は保存しない。1〜3穴で再読込しても未選択穴から続行できる。既存4穴設定はそのまま表示して再抽選を強制しない。
- 抽選リセットは幹事details内に置く。回転中の候補は確定扱いにせず、タブ/結果種目/ゲーム切替、画面非表示、import/削除では回転停止。古いコールバックで別ゲームを書き換えない。
- スコア・par・申告・hidden・参加者/所属の変更は、発表取消と計算結果3列の再マスクを行う。ゲームの保存前フック `hjBeforeSave(state)` が揮発スナップショットで変化を検出する。importの新オブジェクトは基準を初期化し、保存済み発表フラグを不必要に消さない。
- `hjCanAnnounce(g)` を共通判定、`hjStopSpin()` を中断フックとする。表示テーマ・3言語・既存計算は維持する。
- 追加検証：5列独立開示、開示前の順位漏れなし、4回STOPの一意性・再開・旧4穴互換、連打/画面切替停止、入力変更の発表取消、長いフルネームの狭幅、帳票の既存ゲートを確認する。

### 4.4 暫定表示と連携位置（ユーザー追加指示・4.3の表示制限を置換）

- 列開示の初期値は申告/実打/4穴置換後が閉、差/ペナルティが開。4穴置換後も抽選前から開閉可能。
- 表示用計算は抽選確定済みの0〜4穴だけをパーに置換する。0穴では実打合計を表示し、STOPで1穴確定するたびに再計算する。回転中の未確定候補は使わない。
- 表示用の暫定計算を新設し、正式な `hjPlayer`/`hjStanding` の4穴・18H・全員申告の成立条件は維持する。未入力の生スコアを0点扱いしたり、18Hへ推測で引き伸ばしたりしない。
- 4穴未確定の表示値・チーム合計・順位は「暫定」と明記し、計算可能な対象全員がそろえば発表/連携前にも表示する。欠損者を除外したチーム合計は出さない。
- 入力/穴変更時は正式連携を取り消すが、開閉状態は維持して開いた列の暫定値を更新する。利用者が閉じた列は再び勝手に開かない。
- 結果連携ボタンはスコア表示エリアの右下（表の直後、ルーレットの前）に常時配置し、幹事detailsから移動。正式成立前は無効、成立後に連携可能。
- 総合勝ち点と帳票は従来どおり正式4穴・全対象入力完了・連携済みのANDで算入し、暫定結果を公開成績へ加算しない。

### 4.5 チーム帯と4枠一括回転（ユーザー追加指示）

- 大学名の行は他競技のスコア表と同じ、チーム色の帯と対照文字色にする（ライト時は白文字、ダーク時は既存のbgトークンで調整）。
- STARTは1回だけ。未確定の枠すべてを同時回転させ、STOPのたびに左から1枠だけ確定し、残りの枠は回転を継続。4枠目で終了する。
- 各表示フレームの候補も重複させず、確定済み穴を除外する。残り1〜3枠からの再開にも対応。
- 自身のSTOPによる確定穴保存では残りの回転を止めない。外部の入力変更・画面切替・非表示・取込時の停止と、古いイベント/コールバック拒否は維持する。
- 各STOPは呼出時の確定枠数と回転世代で検証し、置換前の古いボタンイベントが続けて枠を確定するのを防ぐ。新しいSTOPボタンは次の1枠を確定できる。
- 回転候補は暫定計算へ入れず、STOP済みの穴だけで再計算する。

## 6. 受け入れ条件・検証

1. 既存全回帰の値、旧1v1配点、大学対抗の every OFF/ON・暫定HDCPが不変。新機能OFF時の出力不変。
2. 複合1v2/2v1/2v2・every0/1/2・平均x.5・half・不足・無効side・重複組を検算。勝/負/ASとも個人m1加算0。
3. scalar/string混在ゲームで旧試合だけ個人加算。複合の順序入替、編集、移動、削除、開始1/10/任意、再生・開封を確認。
4. 上限2方式×男女×every ON/OFF×18H/途中を検算。通常HDCP40未満等、cap変更が効かないケースも確認。
5. HJの差正/負/0、合計同点0.5、重み0/2、3チーム、未宣言、1人丸ごと未入力、置換穴未入力、不正par/hiddenを検証。
6. HJで every を変えても結果不変、DP12変更とHJ4変更が互いに非干渉。選手削除・参加解除・追加で母数/不足が正しく更新。
7. 旧バックアップ移行・新データ往復・複製・再読込を確認。未発表/取消のHTML・sheetモデルに値を漏らさない。既存競技の未開封マスクは維持。
8. `node tools/verify.mjs` と `node tools/regress.mjs` 全実行。新式の期待値は手計算例と照合し、既存期待値の安易な更新は禁止。
9. ブラウザは複合マッチの編集→開始→再生、HJ入力→不足→発表→取消、大学上限切替を最小実測。長名の狭幅を1点確認。
