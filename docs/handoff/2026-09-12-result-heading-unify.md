## 1. 要件（ユーザー原文・2026-09-12）

> 見出しはなしで良いと思ってる。その代わり選択したタブのボタンフォントをを大きく表示したい。

分解:

- **(A)** 結果発表の各カードの `<h2>` 見出しを廃止する（タブ名が見出しを兼ねる）
- **(B)** 選択中のゲームタブのボタンのフォントを大きくする
- **(C)** 連携ボタンを「チーム合計得点カードの右下」に統一配置する
- **「統一して」＝結果発表の全タブ横断**（ニアドラ単独ではない）

### 3.4 ホーム配下タブとの一貫性について

- **対象外とする。** ホーム配下（基本設定・ゲーム設定・コース・選手・スコア）は**1タブに複数の独立したカードが並ぶ編集画面**であり、タブ名がカード見出しを兼ねられない（例: ゲーム設定タブには「採用フォーマット」「配点」「隠しホール」等が同居）。

- 一貫性の観点で1点だけ記録: **`.card h2` の CSS 自体は一切変更しない**ため、ホーム配下の見た目は**1px も変わらない**。本件は「h2 を出力しない」だけの変更。

## 4. 決定(A')：見出しに同居していた状態表示の移動先

### 4.1 統一パターン：カード末尾の共通フッタ行

**全タブで同じ1行にする。**

```
<div class="cardtools mt8">[状態タグ…（左）]            [幹事操作（右端）]</div>
```

- `.cardtools` は既存クラス（`display:flex; flex-wrap:wrap; gap:6px; align-items:center`）。**新規 CSS クラスもトークンも作らない。**
- 右端寄せは `tpAnnounceUI()` が返す `<span style="...margin-left:auto">` がそのまま担う＝**`tpAnnounceUI` のシグネチャ・戻り値は不変**。
- この行は **gross/net/hbh/b2/vegas が既に使っている形**（`roulette.js:250`）。つまり「ほかの全タブをこの形に合わせる」＝統一。
- **順序は「結果 → 状態 → 操作」**（投影原則 §11.14-3「幹事の操作UIは控えめ配置」）。

### 5.3 「右下」が成立しない2タブの扱いと理由

#### A. 1 on 1（現状維持）

- **理由1（縦スペース）**: 連携UIは sticky ブロック内の操作バー（`.reveal-bar`）に**既存行と同居**しており追加高さ0。サマリカードの下に専用フッタ行を作ると **sticky 固定領域が +33〜52px 増える**。`2026-08-20-results-regroup.md` §8.3 の実測どおり、1 on 1 は 320×568 で固定領域が既に ≈359px（可視 ≈209px）＝**これ以上増やせない**。
- **理由2（原則は満たしている）**: 操作バーは sticky ブロックの**最下段**であり、連携UIはその**右端**＝ブロック単位で見れば「右下」になっている。
- **理由3（意味）**: 1 on 1 の「チーム合計」は `.m1-teamsum`（A 3–1 B）で、同じ sticky ブロック内にある。ブロック＝1枚のカードとみなせる。

#### B. ルーレット（18H後のみ行順入替・進行中は現状維持）

- **18H後**: 現在 `rl-head`（リセット＋連携）→ `standRow`（チーム別取得H）の順。これを **`standRow` → `rl-head` の順に入れ替える**。
  - 結果が先・操作が後＝**投影原則 §11.14-3 に元から適合していなかった箇所の是正**にもなる。
  - **追加高さ0**（行の順序を入れ替えるだけ）。連携UIは自動的に「チーム合計（取得H）の右下」に来る。
- **進行中（<18H）**: `rl-head` はホール番号・Par・大型勝敗表示を含む**ライブ演出のヘッダ**であり、カード末尾は大型メインボタン（START/STOP/確定）。連携UIをメインボタンの隣に置くと**誤タップの危険**があり、投影原則の「1画面1主役」にも反する。**現状維持**（リセットの右隣）。
  - 進行中に連携する運用は稀（結果未確定）。18H後が主たる連携タイミング。

```css
@media(min-width:820px){

}
```

- **決め方の根拠**: 「選択中のゲームタブ＝旧 `.card h2` と**同じフォントサイズ**」。見出しが担っていた視覚的な重みを**数値で等価に**引き継ぐ。恣意的な数字を置かない。

- **ゲームタブは 768px で段差を付ける**（既存 `#view-result .subtab-games button` の 768px ブレークポイントに乗せる＝新規 `@media` を作らない）。
- **グループタブは 820px で段差を付ける**（既存 `#view-result .subtab4 button` の 820px ブレークに乗せる）。

### 8.3 行のガタつきは起きない（証明）

- `.subtab-games button{min-height:var(--h-tabrow); padding:0 12px}`（**縦 padding 0**）＝行高は `min-height`（44px／≥1024 で 48px）が支配。
- `.subtab-games{display:flex}` の `align-items` は既定 `stretch` ＝**全ボタンが行の最大高に揃う**。
- 19px の行ボックス = 19 × 1.45 = **27.55px** < 44px。**余裕 16.45px**。
- 行高が変わり始めるのは font-size が **44 / 1.45 = 30.3px** を超えたとき。19px はその 63%。
- → **選択中タブだけ大きくしても行高は 1px も変わらない。** `min-height` 等の追加吸収策は不要。
- 同様に `.subtab4 button`：17 × 1.45 = 24.65px < 44/48px。**折り返さない限り**行高不変（折り返すと 49.3px で +5px。§8.4 で回避を確認）。

**静止画モックではなく「実装後プレビューでの承認」を推奨する。**

| 観点 | 静止画モック | 実装後プレビュー |

## 16. 推奨 PR 分割

**1 PR にまとめる**（CLAUDE.md「関連する小変更は 1 Issue＋1PR」）。

理由: (A) と (B) を別 PR にすると**中間状態が公開される**。
- (B)→(A) の順: 「大きいタブ ＋ 見出し」で見出しが二重＝冗長
- (A)→(B) の順: 「見出しなし ＋ 小さいタブ」＝**どの画面か分からない状態**が公開される（投影ユースで致命的）
